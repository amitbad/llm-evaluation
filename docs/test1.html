Phase 1 — First Experiments

Test 1: Basic Test

Single prompt across all models to check basic functionality, response quality and speed. The first script to run in the whole repository.

📁 phase-1-first-experiments/test1_basic_test.py

How to Run

cd phase-1-first-experiments
python3 test1_basic_test.py

The script prints a banner before starting so you know what it is doing, then queries each model one at a time with a live "waiting…" indicator. You will see output immediately as each model responds — you do not need to wait for all models to finish.

Dependencies & Run Order

✔ No prior test needed. This is the first script to run.

Before running, make sure:
 • ollama serve is running in a separate terminal
 • All models in config.yaml → phase1.MODELS are pulled (ollama pull <model>)

After this: run test2_full_evaluations.py → then test2_score_evaluations.py

What the Terminal Shows

The script prints a coloured intro block explaining what it will do and which models it will query. Then for each model it prints [1/N] Querying <model> ... Sending prompt — waiting for response... followed by the full response and time as soon as it arrives. No silent waiting.

What We Tested

A single joke prompt sent to all models. Goal: see if models respond at all, how fast they are, and whether responses differ in style.

Prompt used: "Hello, can you tell me a short joke?"

Key Learnings

  • Three models gave the same joke. deepseek, mistral and gemma all answered with the "atoms make up everything" joke — suggesting overlap in training data. llama chose a different one entirely.
  • Style differs even when content is the same. deepseek added a polite intro ("Certainly!"), gemma added an emoji, llama added a chatty follow-up question. Same task, different personalities.
  • Speed varies a lot. Mistral answered in 11 seconds. deepseek took 54 seconds — nearly 5x slower. For a production system, this matters. Slower does not always mean better.
  • This is the simplest possible evaluation. One prompt, four outputs, one human reading the results. Everything from here builds on making this process more systematic and scalable.

What's Next — After This Test

Step 2: Run test2_full_evaluations.py

Test 1 only sends one prompt and prints the result. That tells you whether models work and how fast they are — but it says nothing about quality across different types of tasks.

Test 2 is the next script to run. It sends 3 different prompts (a story, a factual question, a summary) to all your models, 3 times each, and saves every response to a file called evaluation_results.json.

⚠ Warning: Test 2 takes a long time — roughly 1–4 minutes per model call. With 4 models × 3 tasks × 3 runs = 36 calls, expect it to run for 30–90 minutes. Start it and leave it running.
Step 3: Run test2_score_evaluations.py (after Step 2 finishes)

Once evaluation_results.json exists, this script reads it and walks you through each response one by one, asking you to rate it 1–5 on metrics like coherence, accuracy, and conciseness. No model is called — you are the judge. Takes about 10–15 minutes of reading and typing. Your scores are saved to scores.json.
