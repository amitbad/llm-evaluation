# Original TestNeural experiments · runner and replay guide

This guide maps the [historical catalog](original-experiments.json) to the archived source and saved artifacts. Start with the offline column. Opening a saved report or inspecting a saved JSON file makes no model call and incurs no provider charge. A report shows what was captured for that run. It cannot establish that the original response, timings or environment can be reproduced.

Use Python 3.10+ as the repository's starting point for a fresh runner. The historical Python and package lockfiles were not recorded. The package names below come from imports, including the runner's local helpers. Package and model versions still need compatibility checks before a fresh run. Use a disposable checkout and a separate virtual environment for each framework. Several runners replace local artifacts or expect files beside the script. Keep the original evidence intact. Use the checked-in defaults only after inspecting the named section of [config.yaml](../config.yaml), and stop before any provider call if the provider or cost is unclear.

**Provider flags.** **Offline** makes no model call. **Local** needs a running Ollama service and the configured model, without metered inference under local defaults. Embedding weights and datasets can require downloads. **Metered** uses an external provider with credentials and may incur charges. Shared-client runners use `requests` and can switch from Ollama to a remote provider via the named configuration. Credentials belong in private environment variables. **Observability** can transmit traces and consume hosted quota. The saved alternatives avoid those side effects.

Supporting input preparation also has side effects. Tests 9 and 11 each have a local `chunker.py` that uses only standard Python to turn its own `documents/` into `chunks.json` and can replace that file. Their `retriever.py` demos use `numpy`, `sentence-transformers` and those chunks to print retrieval results without calling the assistant. Test 14's [create_test_cases.py](../phase-5-production-eval/langfuse-observability/create_test_cases.py) uses `openpyxl` to rebuild its workbook from built-in rows. These are preparation steps. The saved reports do not depend on rerunning them.
