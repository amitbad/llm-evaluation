What We Built and Tested

A banking chatbot (llama3.1:8b) with a system prompt restricting it to Global Bank products. We then built an evaluation suite — test cases stored in Excel, a script to run them, and keyword-based pass/fail rules.

How to Run

cd phase-2-evaluation-techniques/banking-bots
python banking_evaluator.py

Choose your mode when prompted: a for automated eval, m for multi-turn demo, i for interactive chat.

Key Learnings

  • LLMs are non-deterministic — structured eval is essential. An LLM can answer the same question differently on every run. An automated suite gives you repeatable, comparable results.
  • Prompt Injection is a model-level weakness — not fixable by prompt. llama3.1:8b failed 81% of injection tests. This cannot be fixed by writing a better system prompt. In production it requires a guardrail layer or a larger model.
  • Confabulation is the most dangerous hallucination type in finance. When the bot invents a specific account balance, a real customer could make financial decisions based on completely fabricated data. This is a compliance risk.
  • Partial failures are real. A response can pass one check and fail another in the same turn — correctly refusing a request but then hallucinating contact details in the same reply.
  • Evaluation is a separate skill from building. Knowing how to measure whether an AI system is working correctly is often harder — and more valuable — than building it.
  • The attribution problem: When a test fails, is it the model, the prompt, or the test case itself that is wrong? Learning to ask this question is a core GenAI evaluation skill.

What This Evaluation is Called

This is Functional / Deterministic Evaluation of a domain-restricted chatbot — a form of black-box behavioural testing. Pass/fail is decided by explicit, hard-coded rules rather than another model or a human scorer.
