Your Evaluation
Learning Journey

Built for anyone who needs to test and evaluate LLM-based systems — QA Engineers, Test Engineers, developers writing eval scripts, or anyone at any stage of building or validating a GenAI product. Every concept is taught through a real exercise — you build it, run it, and understand why it behaves the way it does. No data science background required.

Who this is for. QA Engineers, Test Engineers, and Test Architects moving into GenAI evaluation roles. You do not need to understand the mathematics behind LLMs. What you need — and already have — is the instinct to find failure modes, design test cases, and think in coverage. That instinct is the most valuable skill in GenAI evaluation. This repository shows you how to apply it.
What this is not. Not a framework. Not an academic course. Not a tutorial with pre-filled outputs. Not model-specific. You build the evaluation logic yourself using real scripts, run them against real models, and read real results. Phase 4 onward introduces production frameworks — this teaches you the concepts first so those frameworks make sense when you reach them.
The gap this fills. Search for LLM evaluation resources and you will find maths-heavy papers, framework docs that assume prior knowledge, and courses designed for data scientists. None of them are built for QA engineers. This repository covers the same techniques used by evaluation teams at AI companies — taught through test design, coverage thinking, and failure analysis. QA language. QA framing. Single place. In order. With real results documented at every step.
Take your time. Each phase builds on the one before. Read every test page fully, run the exercise yourself, and understand the results before moving on. Do not try to match the documented numbers — LLMs are non-deterministic and your outputs will differ. That is expected. Focus on understanding what your results mean, not reproducing what is shown here.
Model providers: All scripts run on local Ollama models by default — free, no account, zero cost. Ollama was used here to allow hundreds of iterations without API spend. You are free to use paid providers — change BOT_PROVIDER or JUDGE_PROVIDER in config.yaml. Bot and judge can use different providers. See .env.example for API key setup.
