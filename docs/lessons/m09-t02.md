## Beginner Explanation

### Open one record before choosing a metric

Northstar’s Q1 asks, “How long do I have and what proof is required?” A case ID ties this task to its reference. A dataset version identifies the frozen set of tasks and source labels. A system version identifies which configuration produced this capture. An answer string records what it actually said. The ordered retrieved IDs and their passage texts record what it had to work with.

Store a reviewed answer separately from the captured answer. The reviewed answer covers the limit and proof. Store IDs for acceptable supporting passages separately from what appeared in the prompt. A **required field** must exist for the declared check. A **reference answer** is optional for faithfulness and required for the reference-based recall example. Reviewed passage IDs are required for our retrieval counts. A citation points from a claim to evidence. Its source ID and revision tell you what text to open.

To **freeze** a RAG record, preserve the exact question, answer, ordered context, source versions, reference revision, and system version. In production also save response ID, model and prompt versions, retrieval settings, and capture timestamp. If V2 produces new answers, freeze them under V2 on the same questions. Scoring an old capture establishes what the evaluator sees in that record. To measure future retrieval, capture a new run. If policy or labels change, give them a new revision and score both systems under the same expectations.

### Ask separate questions of the same answer

Suppose the current policy says 30 days. Predict which replies would pass a policy check and which would pass a support check.

- **Correct and supported.** The reply says 30 days and the supplied current refund passage says 30 days.
- **Correct but unsupported.** The reply says 30 days and the supplied context is about shipping.
- **Incorrect but supported.** The reply says 90 days and the supplied obsolete refund passage says 90 days. The approved policy still says 30.
- **Incorrect and unsupported.** The reply says 90 days and only the current 30-day rule was supplied.

**Correctness** asks whether a claim agrees with the governing policy. **Faithfulness** asks whether the supplied context supports what the assistant said. Completeness checks that the answer addresses both deadline and proof. A valid citation must lead to a supplied, appropriate passage and support its associated claim. Check it independently. A **critical policy failure**, such as promising a refund to a customer outside the deadline, can block release even when averages improve.

### Count retrieved evidence before asking a judge

Suppose `RF` gives the deadline and `MR` gives the required proof. The captured list is `RF, SH, WA`. Only `RF` belongs to the reviewed relevant set. It is one true positive. `SH` and `WA` are two false positives, since they were retrieved but are irrelevant. `MR` is one false negative, since it was required but absent. Precision is `1/3` retrieved passages relevant. Recall is `1/2` expected passages found. A list with zero matches and a nonempty gold set can score zero recall. An empty retrieved list has no precision denominator under this lesson’s rule. Missing gold labels require review or a skip.

Move `RF` from first to last and leave `SH` and `WA` in the list. Predict the two fractions again. Precision is still `1/3` and recall is still `1/2`. The list contains the same IDs, so our **passage-ID overlap** rule returns the same result. A ranking-sensitive framework metric can give more credit when the useful passage appears earlier. Record the metric and its scoring rule alongside every number.

### Map the capture before calling a framework

DeepEval is a Python evaluation and testing framework. Its `LLMTestCase` gives a metric the question, actual output, and ordered retrieval context. Faithfulness judges support for generated claims. Contextual relevancy judges which retrieved statements address the question. Those two metrics do not need a reference answer. A threshold turns a score into a metric pass. Calibrate it against reviewed cases. [DeepEval faithfulness](https://deepeval.com/docs/metrics-faithfulness) and [contextual relevancy](https://deepeval.com/docs/metrics-contextual-relevancy).

Ragas provides evaluation datasets and RAG metric variants. In the pinned `0.3.9` walkthrough a `SingleTurnSample` holds `user_input`, `response`, `retrieved_contexts`, and an optional `reference`. Faithfulness estimates the share of response claims supported by retrieved text. `LLMContextRecall` checks claims in the reference answer, so it needs the reference. The reference-based **context precision** variant judges usefulness for the reference and rewards relevant passages placed earlier. The without-reference variant uses the generated response instead. Other variants compare text or check IDs. **Response relevancy** in the documented LLM-and-embedding variant creates questions from the response and compares their embeddings with the original question. It needs a judge and an embedding model. [Ragas context recall](https://docs.ragas.io/en/v0.3.9/concepts/metrics/available_metrics/context_recall/), [context precision](https://docs.ragas.io/en/v0.3.9/concepts/metrics/available_metrics/context_precision/), and [response relevancy](https://docs.ragas.io/en/v0.3.9/concepts/metrics/available_metrics/answer_relevance/).

An **adapter** maps the saved question to `input` or `user_input`, saved answer to `actual_output` or `response`, and ordered passage text to `retrieval_context` or `retrieved_contexts`. Keep passage and case IDs outside the framework object. Map results back to the M09-T01 contract with case and response IDs, evaluator ID and effective version, status, score, verdict, reason, and error. If the framework returns only a score, document a threshold before setting a pass verdict. Compare scores only after checking the implementation, denominator, scale, model, prompt, threshold, and handling of errors and missing references. Judge responses can vary. Bias, policy ambiguity, and prompt wording can affect verdicts. On a small set one case can move the average considerably.

### Preflight before sending requests

Decide which fields and models each metric needs before execution. Our overlap check uses labeled IDs. The pinned walkthroughs send retained text to a configured judge. The optional Ragas response-relevancy variant also requires an embedding model. Mark missing metric-specific references SKIPPED with no score. Mark malformed required input, unsupported package versions, missing model configuration, timeouts, rate limits, and invalid output ERROR. Preserve the reason and exclude those rows from numeric means. A measured finite zero remains OK.

Use an approved endpoint and keep secrets outside the record. Record versions, model, metric settings, thresholds, timeouts, retries, and cases actually scored. A hypothetical two judge calls on each of eight cases makes 16 calls before retries. Time a small pilot and count requests and tokens before extrapolating. Estimate hosted cost from input and output usage at the approved deployment’s current rates, and include embeddings if used. This chapter has no measured runtime or provider costs for the optional walkthroughs.

### Decide from paired evidence

Pair V2 with V1 by frozen case ID. Show fixes and regressions per dimension. Count evaluated cases beside the average. Ask whether a better mean came from changed behavior or a missing case. For the lab use HOLD for a confirmed critical policy error, REVIEW for unresolved evidence or failed quality criteria, and RELEASE when all paired records are scorable, quality gates pass, and no regressions remain. That decision applies to the teaching fixtures.

### Step 3 — Measure labeled retrieval recall

### Step 4 — Count support for explicit claims

```python
    supported += int(found)
    print(claim, "SUPPORTED" if found else "UNSUPPORTED")

```

```bash
.venv-deepeval/bin/python - <<'PY'
import os
import math
from importlib.metadata import version

if version("deepeval") != "3.7.0":
    raise SystemExit("ERROR: expected deepeval 3.7.0")
if not os.environ.get("OPENAI_API_KEY"):
    raise SystemExit("ERROR: configure an approved judge credential")

from deepeval.metrics import ContextualRelevancyMetric, FaithfulnessMetric
from deepeval.models import GPTModel
from deepeval.test_case import LLMTestCase

case = LLMTestCase(
    input="How long do I have and what proof is required?",
    actual_output="30 days from purchase with a valid receipt.",
    retrieval_context=[
        "Refund requests close 30 days from purchase.",
        "Contact Support after 45 days about a shipping delay.",
        "Start a warranty claim from your order page.",
    ],
)
judge = GPTModel(model="gpt-4o-mini-2024-07-18")
for metric_type in (ContextualRelevancyMetric, FaithfulnessMetric):
    name = metric_type.__name__
    try:
        metric = metric_type(model=judge, threshold=0.7, include_reason=True, async_mode=False)
        metric.measure(case)
        score = metric.score
        if score is None or not math.isfinite(score) or not 0 <= score <= 1:
            raise ValueError("invalid score")
        print("demo-v1/Q1/capture-1", name, "OK", score, metric.is_successful(), metric.reason)
    except Exception as error:
        print("demo-v1/Q1/capture-1", name, "ERROR", type(error).__name__)
PY
```

Read the score and reason for each check. A metric pass just means that metric met its `0.7` demo threshold. For a Python regression assertion use the validated metric verdict in a test and report execution failures separately. An import failure calls for checking interpreter and package versions. Authentication or rate-limit failures call for checking the approved provider account and execution settings. A timeout is an error, even if an older report stored zero. In a CI run record duration and the effective retry budget. Scrub sensitive inputs or reasons before sharing logs.

`user_input` and `response` are the saved Q1 fields. `retrieved_contexts` contains the exact three passages from the DeepEval example. `reference` supplies the reviewed answer used by reference recall. `EvaluationDataset` wraps the sample. This run uses two LLM metrics and no embedding metric. `ChatOpenAI` supplies the judge. This one-case adapter prints the stable case and capture ID outside the framework’s result row.
```bash
.venv-ragas/bin/python - <<'PY'
import os
import math
from importlib.metadata import version

if version("ragas") != "0.3.9":
    raise SystemExit("ERROR: expected ragas 0.3.9")
if not os.environ.get("OPENAI_API_KEY"):
    raise SystemExit("ERROR: configure an approved judge credential")

from langchain_openai import ChatOpenAI
from ragas import EvaluationDataset, RunConfig, SingleTurnSample, evaluate
from ragas.metrics import Faithfulness, LLMContextRecall

sample = SingleTurnSample(
    user_input="How long do I have and what proof is required?",
    response="30 days from purchase with a valid receipt.",
    reference="30 days from purchase with a valid receipt.",
    retrieved_contexts=[
        "Refund requests close 30 days from purchase.",
        "Contact Support after 45 days about a shipping delay.",
        "Start a warranty claim from your order page.",
    ],
)
data = EvaluationDataset(samples=[sample])
judge = ChatOpenAI(model="gpt-4o-mini-2024-07-18", temperature=0, timeout=30, max_retries=0)
for metric in (Faithfulness(), LLMContextRecall()):
    if isinstance(metric, LLMContextRecall) and not sample.reference:
        print("demo-v1/Q1/capture-1", metric.name, "SKIPPED", "missing reference")
        continue
    try:
        result = evaluate(
            dataset=data, metrics=[metric], llm=judge,
            raise_exceptions=True, show_progress=False,
            run_config=RunConfig(timeout=60, max_retries=1, max_workers=1),
        )
        score = float(result.scores[0][metric.name])
        if not math.isfinite(score) or not 0 <= score <= 1:
            raise ValueError("invalid score")
        print("demo-v1/Q1/capture-1", metric.name, "OK", score)
    except Exception as error:
        print("demo-v1/Q1/capture-1", metric.name, "ERROR", type(error).__name__)
PY
```

For a missing-reference test, remove `reference` from the sample and run again. Reference recall skips before sending the request for that metric. Faithfulness can still run with the same answer and passages. Check virtual-environment versions if a metric import fails. If a metric runs but returns NaN, preserve the execution outcome as ERROR. Check the provider and timeout settings when a call fails. Keep the scoring response, error details in an approved log, and effective package versions with the run. A tuple of triples stores claim name, reviewed value, and cited ID. The code uses `set` intersections for precision and recall, and counts each case equally in their means. def verify_cases(records, baseline, candidate):
```python
    ids = [case[0] for case in records]
    if len(set(ids)) != len(ids) or set(baseline) != set(ids) or set(candidate) != set(ids):
        raise ValueError("Expected unique case IDs with one slot per system")
    for case_id, question, reference, gold, facts in records:
        if not case_id or not question or not gold or len(gold) != len(set(gold)):
            raise ValueError("Invalid case or gold IDs")
        if set(gold) - sources.keys() or not facts:
            raise ValueError("Invalid gold source or expected facts")
        if reference is not None and (not isinstance(reference, str) or not reference.strip()):
            raise ValueError("Invalid reference")

def assess(case, row):
    _id, _question, reference, gold, expected = case
    # A known gate can still be evaluated when a capture has another defect.
    annotated = row.get("claims", ()) if isinstance(row, dict) else ()
    valid_claims = isinstance(annotated, tuple) and all(
        isinstance(claim, tuple) and len(claim) == 3 and isinstance(claim[0], str)
        and type(claim[1]) in (str, int, bool) and isinstance(claim[2], str) for claim in annotated
    )
    critical = (_id == "Q8" and valid_claims and any(
        key in expected and (type(val) is not type(expected[key]) or val != expected[key])
        for key, val, _ in annotated
    ))
    if not isinstance(row, dict) or not isinstance(row.get("answer"), str) or not row["answer"].strip():
        return {"status": "ERROR", "error": "missing answer", "critical": critical}
    got = row.get("retrieved")
    if (not isinstance(got, tuple) or any(not isinstance(key, str) for key in got)
            or len(set(got)) != len(got)
            or set(got) - sources.keys()):
        return {"status": "ERROR", "error": "invalid retrieved IDs", "critical": critical}
    if not valid_claims or not annotated or len({key for key, _, _ in annotated}) != len(annotated):
        return {"status": "ERROR", "error": "invalid claim annotations", "critical": critical}
    facts = {(key, val) for key, val, _ in annotated}
    hits = len(set(got) & set(gold))
    matches = (len(facts) == len(expected) and all(key in expected and value == expected[key]
               and type(value) is type(expected[key]) for key, value in facts))
    correct = matches if reference is not None else None

    # Q8 supplies the customer's purchase age in the question. For this exact
    # fixture, the approved deadline rule entails ineligibility on day 45.
    def supports(source, fact):
        key, value = fact
        source_key, source_value = sources[source][1]
        return (key == source_key and type(value) is type(source_value) and value == source_value
                or (_id == "Q8" and source == "RF" and key == "eligible" and value is False))

    support = sum(any(supports(source, fact) for source in got) for fact in facts)
    citations = sum(ref in got and supports(ref, (key, val)) for key, val, ref in annotated)
    return {
        "status": "OK", "precision": hits / len(got) if got else None,
        "recall": hits / len(gold), "correct": correct, "supported": support,
        "claims": len(facts), "valid_links": citations, "links": sum(bool(ref) for _, _, ref in annotated),
        "critical": critical, "ragas_recall": "READY" if reference is not None else "SKIPPED",
    }

def ratio(n, d):
    return f"{n}/{d}" if d else "N/A"

def metric_mean(rows, name):
    scores = [row[name] for row in rows if row["status"] == "OK" and row[name] is not None]
    return f"{mean(scores):.3f} (n={len(scores)})" if scores else "N/A (n=0)"

def totals(rows):
    valid = [row for row in rows if row["status"] == "OK"]
    scored = [row["correct"] for row in valid if row["correct"] is not None]
    return (
        f"P={metric_mean(rows, 'precision')} R={metric_mean(rows, 'recall')} "
        f"correct={ratio(sum(scored), len(scored))} "
        f"claim-support={ratio(sum(r['supported'] for r in valid), sum(r['claims'] for r in valid))} "
        f"citations={ratio(sum(r['valid_links'] for r in valid), sum(r['links'] for r in valid))} "
        f"coverage={len(valid)}/{len(rows)} errors={len(rows)-len(valid)} "
        f"reference-skips={len(valid)-len(scored)} critical={sum(r['critical'] for r in rows)}"
    )

def compare(label, records, candidate, baseline=v1, reference_revision="refs-v1"):
    verify_cases(records, baseline, candidate)
    baseline_rows = {}
    candidate_rows = {}
    print(f"{label} | {dataset} | {reference_revision} | {rubric}")
    print("Case | V1 P/R answer | V2 P/R answer | V2 support | Ragas reference recall input")
    for case in records:
        key = case[0]
        left = baseline_rows[key] = assess(case, baseline[key])
        right = candidate_rows[key] = assess(case, candidate[key])
        def compact(row):
            if row["status"] == "ERROR":
                return "ERROR " + row["error"]
            precision = "N/A" if row["precision"] is None else f"{row['precision']:.2f}"
            correct = "SKIPPED" if row["correct"] is None else "PASS" if row["correct"] else "FAIL"
            return f"{precision}/{row['recall']:.2f} {correct}"
        support = ratio(right["supported"], right["claims"]) if right["status"] == "OK" else "N/A"
        print(f"{key} | {compact(left)} | {compact(right)} | {support} | {right.get('ragas_recall', 'ERROR')}")
    old, new = list(baseline_rows.values()), list(candidate_rows.values())
    paired = [(baseline_rows[key], candidate_rows[key]) for key in baseline_rows
              if baseline_rows[key]["status"] == candidate_rows[key]["status"] == "OK"]
    equality = [(a["correct"], b["correct"]) for a, b in paired
                if a["correct"] is not None and b["correct"] is not None]
    recalls = sum(b["recall"] < a["recall"] for a, b in paired)
    unsupported = sum(b["supported"] < b["claims"] for b in new if b["status"] == "OK")
    citation_gaps = sum(b["valid_links"] < b["claims"] or b["valid_links"] < b["links"]
                        for b in new if b["status"] == "OK")
    paired_precision = [(a["precision"], b["precision"]) for a, b in paired
                        if a["precision"] is not None and b["precision"] is not None]
    before = f"{mean(x for x, _ in paired_precision):.3f}" if paired_precision else "N/A"
    after = f"{mean(y for _, y in paired_precision):.3f}" if paired_precision else "N/A"
    decision = "RELEASE"
    if any(row["critical"] for row in new):
        decision = "HOLD"
    elif (not records or len(equality) != len(records)
          or any(not correct for _, correct in equality) or recalls or unsupported or citation_gaps):
        decision = "REVIEW"
    print("RAG-V1:", totals(old))
    print(label + ":", totals(new))
    print(f"Paired precision: {before} -> {after} (n={len(paired_precision)})")
    print(f"Answer fixes={equality.count((False, True))} regressions={equality.count((True, False))}"
          f" (n={len(equality)}) | retrieval recall regressions={recalls}"
          f" | unsupported cases={unsupported} | citation gaps={citation_gaps}")
    print("Decision:", decision)
    return json.dumps({"system": label, "dataset": dataset, "rubric": rubric,
                       "source_revision": "northstar-policy-v2", "sources": sources,
                       "reference_revision": reference_revision, "cases": records,
                       "baseline": baseline, "captures": candidate,
                       "baseline_results": baseline_rows, "results": candidate_rows,
                       "decision": decision}, sort_keys=True, allow_nan=False)
```

## Common Mistakes

- Re-running retrieval during evaluation of saved captures and mixing the resulting contexts.
- Giving a timeout a numeric zero or treating a missing reference as a model error.
- Passing a judge metric on an old policy and treating that result as approval of the current answer.
- Comparing similarly named metrics without checking their variants and judge settings.
- Treating high retrieval precision as permission to ignore a critical answer regression.

## Lesson Summary and Next Step

Freeze the evidence before you compare versions. Score retrieval, answer correctness, claim support, and citations on their own terms. Map the same saved records into each metric configuration, preserve failures and skips, and apply the release gates to matched evidence.
