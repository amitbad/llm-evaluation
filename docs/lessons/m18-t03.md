## Beginner Explanation

A **research question** identifies what to learn. For Northstar, it is whether B grades answers more accurately than the current A on justified refund decisions. A **hypothesis** predicts a measurable result, such as “B will improve agreement with adjudicated labels without adding critical false approvals.” A **method** defines how to do the comparison. An **experiment** applies that method under recorded conditions. A **dataset** is the set of cases and labels. A **baseline** is the reference approach, such as the approved judge or a simpler deterministic check. A **metric** is a defined measurement, such as correct verdicts divided by all paired cases with verified labels.

A **result** is what was measured. A **conclusion** interprets the result under the experiment's assumptions. A **limitation** sets a boundary on that interpretation. **Statistical uncertainty** concerns how estimates could vary across samples or runs. **External validity** asks whether the result transfers to another population or environment. For example, one refund-policy slice gives little evidence about multilingual refusals, agent tool decisions or newer policies. New modalities, workflows, policies, model behaviors and operating costs change what evaluations need to measure.

This lesson uses **reproduction** for recomputing a result from the original inputs and procedure, and **replication** for testing the same question with new data. Terms vary across fields, so declare how you use them. A **preprint** is a publicly circulated manuscript that may precede formal review. **Peer review** is scrutiny by other experts before publication. It provides feedback and a record of review. Independent implementation and evidence checks still matter. [National Academies, Reproducibility and Replicability in Science, 2019](https://nap.nationalacademies.org/catalog/25303/reproducibility-and-replicability-in-science)

## Worked Demonstration

### Experiments A through C — Audit a claim against paired evidence

The fictional report gives A five correct verdicts and B seven on the same eight cases. It claims lower operating cost and suitability for release. It omits cost records, sampling and applicability details, and the effect on critical cases. The capture below preserves independent reference labels. PASS is the positive class: approving a prohibited reply is a false positive. Accuracy counts all matches, precision asks how often approved replies deserved approval, recall asks how many acceptable replies were approved, and F1 balances precision and recall.

A single verdict in eight moves accuracy by 12.5 percentage points. For uncertainty use the exact two-sided paired test on the cases where only one judge is correct. If under the null each independent discordant pair is equally likely to favor A or B, one or zero B wins among four has probability 5/16. Symmetrically three or four B wins has another 5/16. The result is 0.625. This test is appropriate for the stated paired null and independence assumption. Related families should be grouped or analyzed differently, and the stress fixture cannot support population inference. A p-value cannot set the operational value of an effect. [Fay, Two-sided Exact Tests and Matching Confidence Intervals for Discrete Data, 2010](https://journal.r-project.org/articles/RJ-2010-008/)

[Open Python Editor](https://www.online-python.com/)

```python
from math import comb

# Case, type, reference, Judge A, Judge B, critical if falsely approved.
rows = [
    ("R01", "refund", "PASS", "PASS", "PASS", False),
    ("R02", "replacement", "PASS", "PASS", "PASS", False),
    ("R03", "clarification", "PASS", "BLOCK", "PASS", False),
    ("R04", "valid refusal", "PASS", "PASS", "PASS", False),
    ("R05", "unsupported amount", "BLOCK", "BLOCK", "BLOCK", False),
    ("R06", "missing disclosure", "BLOCK", "PASS", "BLOCK", False),
    ("R07", "foreign field", "BLOCK", "BLOCK", "PASS", True),
    ("R08", "wrong ordinary deadline", "BLOCK", "PASS", "BLOCK", False),
]


def metrics(index):
    tp = fp = tn = fn = 0
    critical = []
    for case in rows:
        case_id, _, gold, _, _, severe = case
        verdict = case[index]
        tp += gold == verdict == "PASS"
        tn += gold == verdict == "BLOCK"
        fp += gold == "BLOCK" and verdict == "PASS"
        fn += gold == "PASS" and verdict == "BLOCK"
        if severe and gold == "BLOCK" and verdict == "PASS":
            critical.append(case_id)
    return tp, fp, tn, fn, critical


for judge, index in (("A", 3), ("B", 4)):
    tp, fp, tn, fn, critical = metrics(index)
    print(f"{judge}: {tp+tn}/{len(rows)}, precision={tp/(tp+fp):.3f}, recall={tp/(tp+fn):.3f}, "
          f"F1={2*tp/(2*tp+fp+fn):.3f}, critical={critical}")

gains = sum(gold == b and gold != a for _, _, gold, a, b, _ in rows)
losses = sum(gold == a and gold != b for _, _, gold, a, b, _ in rows)
discordant = gains + losses
tail = sum(comb(discordant, k) for k in range(min(gains, losses) + 1))
p = min(1, 2 * tail / 2**discordant)
print(f"paired: +{gains}/-{losses}, delta={(gains-losses)/len(rows):+.1%}, exact p={p:.3f}")
print("cost claim: unverified")
```

Recorded local output.

```text

B: 7/8, precision=0.800, recall=1.000, F1=0.889, critical=['R07']
paired: +3/-1, delta=+25.0%, exact p=0.625

```

B improves by two net matches but falsely approves R07. The reported accuracy is reproducible from the rows. The cost claim has no denominator or measurements, and release approval would violate a mandatory check. Change B's R07 verdict to BLOCK and inspect both the paired and critical results. A claim can be arithmetically correct and operationally insufficient.

### Read a paper in three passes

Start with the decision you need to make, such as whether a smaller review queue can retain useful estimates. Search by the problem and terms such as “active testing” and “evaluation sampling bias.” Prefer the paper and code or data release for claims. Follow citations forward to corrections and independent tests, and back to baselines. Record the version and publication date you read.

| Paper reading pass | What to read | What to write down |
| --- | --- | --- |
| First pass | Title, abstract, introduction, contribution and conclusion | The research question, central claim, intended users and expected benefit in one sentence |
| Second pass | Methods, datasets, baselines, metrics, setup and assumptions | Case selection, versions, comparator, label provenance, budgets and which variables changed |
| Third pass | Results, ablations, error analysis, uncertainty, limitations and ethics | What the evidence supports, where it fails, what is missing and a concrete independent test |

Try the worksheet on *Active Testing: Sample-Efficient Model Evaluation* by Jannik Kossen, Sebastian Farquhar, Yarin Gal and Tom Rainforth (ICML 2021). It motivates carefully selecting cases to label and correcting selection bias for estimation. Its demonstrations include Fashion-MNIST and CIFAR-100. Before transferring the claim to support evaluation, ask whether you can record selection probabilities and obtain independent human labels for the new task. ### Experiment D — Remove one guard at a time

An **ablation** compares a full method with a variant having one part removed. Predict what happens when only authorization is removed. Then remove both policy evidence and authorization to see whether a case depends on either of two guards. Each Boolean below is the result of a separate synthetic check. The policy labels and criticality come from an independent reference.

[Open Python Editor](https://www.online-python.com/)

```python
checks = ("correctness", "evidence", "authorization", "structure")

    ("D04", ("authorization",), False, True),
    ("D05", ("structure",), False, False),
    ("D06", ("evidence", "authorization"), False, True),

variants = [("full", ())] + [(name, (name,)) for name in checks]
variants.append(("evidence + authorization", ("evidence", "authorization")))

for name, removed in variants:
    active = set(checks) - set(removed)
    outcomes = [(case_id, active.isdisjoint(fails), gold, critical)
                for case_id, fails, gold, critical in cases]
    matches = sum(accepted == gold for _, accepted, gold, _ in outcomes)
    critical_misses = [key for key, accepted, gold, critical in outcomes if accepted and not gold and critical]
```

### Experiment E — Compare discovery, estimates and effort

A **static benchmark** fixes test selection in advance. **Active evaluation** chooses which cases to label to answer a goal under a budget. A difficulty or risk score can prioritize hard cases. An uncertainty estimate can point to cases on which a judge is least confident. A coverage rule can reserve some budget for otherwise neglected areas.

Here twelve cases are divided into high-risk and ordinary strata. Predict which strategy exposes more critical errors within four labels. The uniform sampler draws four cases from the whole pool. The risk-weighted sampler draws three high-risk rows and one ordinary row randomly within strata. Estimate a population failure rate for that design by weighting each stratum's sample rate by its population share. A stratum is a group set before sampling. The adaptive policy uses stored uncertainty plus an observed prior failure to choose the next row. It reports discoveries but no population estimate. The synthetic label minutes reflect review effort. An equal label count need not imply equal cost.

[Open Python Editor](https://www.online-python.com/)

```python
from random import Random

SEED = 17
# ID, stratum, uncertainty before labeling, failure, critical, synthetic minutes
pool = [
    ("E01", "high", .44, True, True), ("E02", "high", .33, True, True),
    ("E03", "high", .29, True, False), ("E04", "high", .21, False, False),
    ("E05", "ordinary", .49, True, False), ("E06", "ordinary", .48, False, False),
    ("E07", "ordinary", .42, False, False), ("E08", "ordinary", .25, False, False),
    ("E09", "ordinary", .17, False, False), ("E10", "ordinary", .16, False, False),
    ("E11", "ordinary", .10, False, False), ("E12", "ordinary", .07, False, False),
]
# The review-time convention is three minutes for high-risk and one otherwise.
pool = [(*row, 3 if row[1] == "high" else 1) for row in pool]
groups = {group: [row for row in pool if row[1] == group] for group in ("high", "ordinary")}
rng = Random(SEED)
uniform = rng.sample(pool, 4)
rng = Random(SEED)
risk_weighted = rng.sample(groups["high"], 3) + rng.sample(groups["ordinary"], 1)


def adaptive(pool, budget):
    remaining = list(pool)
    selected = []
    boost = set()
    for _ in range(budget):
        chosen = max(remaining, key=lambda row: row[2] + (.12 if row[1] in boost else 0))
        remaining.remove(chosen)
        selected.append(chosen)
        if chosen[3]:
            boost.add(chosen[1])
    return selected


weighted = 0
for group, population in groups.items():
    sample = [row for row in risk_weighted if row[1] == group]
    weighted += len(population) / len(pool) * sum(row[3] for row in sample) / len(sample)
for name, rows, estimate in (("uniform", uniform, sum(row[3] for row in uniform) / len(uniform)),
                             ("risk-weighted", risk_weighted, weighted),
                             ("adaptive uncertainty", adaptive(pool, 4), None)):
    ids = [row[0] for row in rows]
    display = f"{estimate:.3f}" if estimate is not None else "not estimated"
    print(f"{name}: {ids}, critical={sum(row[4] for row in rows)}, "
          f"coverage={len(set(row[1] for row in rows))}/2 strata, labels={len(rows)}, "
          f"minutes={sum(row[5] for row in rows)}, observed failures={sum(row[3] for row in rows)}, estimate={display}")
print(f"simulator population failure rate={sum(row[3] for row in pool)}/{len(pool)}")
```

Recorded local output.

```text
uniform: ['E09', 'E07', 'E05', 'E06'], critical=0, coverage=1/2 strata, labels=4, minutes=4, observed failures=1, estimate=0.250
risk-weighted: ['E04', 'E02', 'E03', 'E09'], critical=1, coverage=2/2 strata, labels=4, minutes=10, observed failures=2, estimate=0.222
adaptive uncertainty: ['E05', 'E06', 'E07', 'E01'], critical=1, coverage=2/2 strata, labels=4, minutes=6, observed failures=2, estimate=not estimated
simulator population failure rate=4/12
```

The label at a drawn row is read after selection. The uncertainty scores are fictional ranks. The adaptive bonus uses previously observed failures. It can spend more of its budget in one stratum. Try removing the bonus and compare coverage. The simulator knows the full-pool rate, which live sampling generally does not. Stratified weighting corrects unequal planned sampling fractions in expectation when draws are random within strata. One sample can still be far from the population rate. A deterministic adaptive queue has no valid population estimator by default. Keep a probability sample for estimation and a separate targeted stream for finding serious failures.

### Experiments F and G — Validate generated cases and controlled changes

Synthetic test generation can expand wording, language and boundary coverage. A generator can also change a material fact while labeling the case as equivalent. Start with a redacted behavioral simulation. It retains policy facts needed for grading and replaces identifiers with fictional values. In a real replay, check for remaining sensitive content and spurious cues from redaction before using a case.

A **counterfactual pair** changes one relevant fact while keeping the others fixed. Here the reference expects a verification request when ownership is unknown, a denial when the account is different, and a different eligibility decision beyond 30 days. A wording or language change should preserve the decision. If a wording variation also changes ownership, you cannot tell which caused the result. That is **confounding**. **Sensitivity analysis** probes whether your conclusion survives reasonable changes to assumptions or cases.

The reference below represents the synthetic policy. The candidate uses age alone, so expect it to mishandle some variants. Before scoring, validate the promised edit and the expected answer. The evaluator must never update authorization or issue a refund here.

[Open Python Editor](https://www.online-python.com/)

```python
base = {"order": "NS-0042", "scope": "same", "age_days": 15,
        "conflict": False, "message": "Can I get a refund?", "locale": "en"}
# ID, proposed change, permitted fields for this variant, claimed reference.
variants = [
    ("F01", {"message": "May I request my money back?"}, {"message"}, "ELIGIBLE"),
    ("F02", {"order": None}, {"order"}, "VERIFY"),
    ("F03", {"conflict": True}, {"conflict"}, "REVIEW"),
    ("F04", {"scope": "other"}, {"scope"}, "DENY"),
    ("F05", {"message": "क्या रिफंड मिल सकता है?", "locale": "hi"}, {"message", "locale"}, "ELIGIBLE"),
    ("G01", {"scope": "unknown"}, {"scope"}, "VERIFY"),
    ("G02", {"age_days": 31}, {"age_days"}, "DENY"),
    ("bad-family", {"message": "Refund please.", "scope": "other"}, {"message"}, "ELIGIBLE"),
    ("bad-label", {"order": None}, {"order"}, "ELIGIBLE"),
]


def reference(row):
    if row["scope"] == "other":
        return "DENY"
    if row["order"] is None or row["scope"] != "same":
        return "VERIFY"
    if row["conflict"]:
        return "REVIEW"
    return "ELIGIBLE" if row["age_days"] <= 30 else "DENY"


def candidate(row):
    return "ELIGIBLE" if row["age_days"] <= 30 else "DENY"


valid = correct = 0
for key, change, allowed, expected in variants:
    row = dict(base, **change)
    changed = {field for field in row if row[field] != base.get(field)}
    gold = reference(row)
    if changed != allowed or gold != expected:
        print(f"{key}: REJECT GENERATED CASE")
        continue
    verdict = candidate(row)
    valid += 1
    correct += verdict == gold
    print(f"{key}: expected={gold}, actual={verdict}, "
          f"reference changed={gold != reference(base)}, candidate changed={verdict != candidate(base)}")
print(f"candidate={correct}/{valid} validated variants")
```

### Experiment J — Decide whether to fund a controlled pilot

Require a complete and reproducible packet, no critical false approval, and the independent test of the proposed method. Check cost, latency, approvals and a verified stop plan. In this lab a passing decision authorizes consideration of a shadow-only pilot with no write authority. A confirmed critical failure or mismatched reproduction is BLOCK. Missing evidence, uncertainty for a stronger superiority claim, or pending human approval is REVIEW. The cost fixture allows 15 label minutes and 1,200 ms as example budgets. The lab intentionally keeps statistical superiority separate from a bounded trial: a neutral or inconclusive quality result cannot justify claiming a win.

```python
from hashlib import sha256
from itertools import product
import json
import platform

EXPORT_JSON = False
CLAIM = "NS-CLAIM-01"
# ID, independent reference, baseline verdict, candidate verdict, severe false-PASS risk
ORIGINAL = [
    ("R01", "PASS", "PASS", "PASS", False), ("R02", "PASS", "PASS", "PASS", False),
    ("R03", "PASS", "BLOCK", "PASS", False), ("R04", "PASS", "PASS", "PASS", False),
    ("R05", "BLOCK", "BLOCK", "BLOCK", False), ("R06", "BLOCK", "PASS", "BLOCK", False),

NEW = [
    ("N01", "PASS", "PASS", "PASS", False), ("N02", "PASS", "BLOCK", "PASS", False),
    ("N03", "BLOCK", "BLOCK", "PASS", True), ("N04", "BLOCK", "PASS", "PASS", False),
    ("N05", "PASS", "PASS", "PASS", False), ("N06", "BLOCK", "BLOCK", "BLOCK", True),
]
# Trusted policy fixture records supplying the separate authorization/privacy check.
DENY_RECORDS = {"R07": "foreign account field", "N03": "ownership denied", "N06": "private detail"}
PUBLISHED = {"raw": {"a": 5, "b": 7, "n": 8}, "guarded": {"a": 5, "b": 8, "n": 8}}
MANIFEST = {
    "experiment": "NS-REPRO-01", "claim": CLAIM,
    "dataset": "northstar-research-original-v1", "replication_dataset": "northstar-fresh-families-v1",
    "version": "northstar-research-runner-v1", "rubric": "northstar-policy-v1",
    "baseline": "judge-a-v1", "candidate": "judge-b-v1", "variant": "guard-v1",
    "metric": "count exact verdict matches over all verified pairs",
    "config": {"pair_key": "case_id", "seed": None, "mode": "frozen deterministic capture"},
    "dependencies": {"python": platform.python_version(), "packages": "standard library only"},
}
APPROVAL = {"scope": "shadow-only", "variant": "guard-v1", "receipt": "synthetic approval"}
BASE_COST = {"minutes": 18, "latency": 1300}


def guarded(rows):
    return [(key, gold, a, "BLOCK" if key in DENY_RECORDS else b, severe)
            for key, gold, a, b, severe in rows]


def compare(rows, method="judge-b-v1"):
    if not rows or len({row[0] for row in rows}) != len(rows):
        raise ValueError("use a nonempty set with unique case IDs")
    groups = {"both": [], "only_a": [], "only_b": [], "neither": []}
    outcomes = {(True, True): "both", (True, False): "only_a", (False, True): "only_b", (False, False): "neither"}
    critical = []
    for key, gold, a, b, severe in rows:
        if any(verdict not in ("PASS", "BLOCK") for verdict in (gold, a, b)):
            raise ValueError("resolve missing or invalid verdicts before comparison")
        groups[outcomes[(a == gold, b == gold)]].append(key)
        if severe and gold == "BLOCK" and b == "PASS":
            critical.append(key)
    losses, gains = len(groups["only_a"]), len(groups["only_b"])
    # The lab fixtures are tiny. Enumerate possible independent directions under H0.
    discordant = losses + gains
    equally_likely = product((0, 1), repeat=discordant)
    observed = abs(gains - losses)
    extreme = sum(abs(2 * sum(trial) - len(trial)) >= observed for trial in equally_likely)
    return {"method": method, "case_ids": sorted(row[0] for row in rows),
            "summary": {"a": len(groups["both"]) + losses, "b": len(groups["both"]) + gains,
                                          "n": len(rows)},
            "paired": groups, "exact_p": extreme / 2**discordant, "critical": critical}


def checksum(value):
    data = json.dumps(value, sort_keys=True, separators=(",", ":")).encode("utf-8")
    return sha256(data).hexdigest()


def reproduce(original, manifest, expected):
    actual = original["summary"]
    required = {"experiment", "claim", "dataset", "replication_dataset", "version", "rubric", "baseline",
                "candidate", "variant", "metric", "config", "dependencies"}
    complete = required <= manifest.keys() and all(manifest[key] for key in required)
    if complete:
        complete = ({"pair_key", "seed", "mode"} <= manifest["config"].keys()
                    and {"python", "packages"} <= manifest["dependencies"].keys()
                    and original["method"] in (manifest["candidate"], manifest["variant"]))
    decision = ("REVIEW" if not complete else "PASS" if checksum(actual) == checksum(expected) else "BLOCK")
    return {"status": decision, "method": original["method"], "expected": expected, "actual": actual,
            "expected_hash": checksum(expected), "actual_hash": checksum(actual), "paired_artifact_hash": checksum(original)}


def adoption(original, fresh, audit, *, approval=None, minutes=None, latency=None,
             stop_plan=False, superiority_required=False):
    if original["critical"] or fresh["critical"] or audit["status"] == "BLOCK":
        return "BLOCK"
    if (audit["status"] == "REVIEW" or original["method"] != fresh["method"] or audit["method"] != fresh["method"]
            or fresh["case_ids"] != sorted(row[0] for row in NEW) or minutes is None or latency is None
            or not approval or approval.get("scope") != "shadow-only" or approval.get("variant") != fresh["method"]
            or not approval.get("receipt") or not stop_plan):
        return "REVIEW"
    if minutes > 15 or latency > 1200 or fresh["summary"]["b"] < fresh["summary"]["a"]:
        return "BLOCK"
    if superiority_required and (fresh["exact_p"] >= .05 or fresh["summary"]["b"] <= fresh["summary"]["a"]):
        return "REVIEW"
    return "PASS"


if __name__ == "__main__":
    original = compare(ORIGINAL)
    fresh = compare(NEW)
    protected_original = compare(guarded(ORIGINAL), "guard-v1")
    protected_fresh = compare(guarded(NEW), "guard-v1")
    audit = reproduce(original, MANIFEST, PUBLISHED["raw"])
    protected_audit = reproduce(protected_original, MANIFEST, PUBLISHED["guarded"])
    incomplete = reproduce(protected_original, {k: v for k, v in MANIFEST.items() if k != "config"},
                           PUBLISHED["guarded"])
    bad_checksum = reproduce(protected_original, MANIFEST, dict(PUBLISHED["guarded"], b=7))
    rich = {"approval": APPROVAL, "minutes": 12, "latency": 1100, "stop_plan": True}
    print(f"reproduce: expected={audit['expected']}, actual={audit['actual']}, "
          f"hash match={audit['actual_hash']==audit['expected_hash']}, {audit['status']}")
    for name, report in (("replicate raw", fresh), ("replicate guarded", protected_fresh)):
        summary = report["summary"]
        print(f"{name}: A={summary['a']}/{summary['n']}, B={summary['b']}/{summary['n']}, "
              f"p={report['exact_p']:.3f}, critical={report['critical']}")
    print(f"synthetic effort: baseline={BASE_COST['minutes']} minutes, guarded={rich['minutes']} minutes, "
          f"latency={BASE_COST['latency']}→{rich['latency']} ms")
```

## Compare Emerging Methods

**Measure validity** asks whether a test measures the intended construct, the property you care about. If you want to measure authorized support outcomes, an evaluator that mainly rewards fluency has poor validity for that task, even if it is consistent. A measure can work well for one purpose and fail when reused for another.

| Method family | What it can improve | What still needs an independent check |
| --- | --- | --- |
| Advanced LLM judges | Rubrics and evidence can make pointwise decisions inspectable. Pairwise judgments compare two outputs. Reference-free judges can help triage open-ended work. | Check calibration, judge bias and shared errors. Multi-judge agreement can reflect the same flawed evidence. Reference-free quality ratings cannot establish authorization. |
| Preference modeling | A learned preference model can approximate rankings from human comparisons. | Blind source identity, reverse orders, check ties and preserve coverage. A preferred answer can still breach policy. Separate preferences from required facts and safety. |
| Process and trajectory evaluation | Inspect intermediate decisions, scoped tool calls, receipts and shared state. Outcome-only scoring is simpler. Process supervision uses intermediate labels, while outcome supervision labels final results. | Check which step actually caused failure. This is credit assignment. A correct reply with an extra write can fail the workflow. Trace gaps limit attribution. |
| Adaptive evaluation | Use recorded risk, uncertainty, difficulty and coverage for targeted labeling. | For population estimates, keep a representative sample or use a justified probability-based estimator. Retain the sampling design and report discovery separately. |
| Adversarial and stress evaluation | Probe defensive assumptions on authorized threat cases such as instruction conflicts, refusal robustness and untrusted tool outputs. Include distribution shifts and rare failures. | Use inert fixtures and scope checks. Finding a weakness in a stress set says little about its frequency in ordinary traffic. |
| Synthetic and redacted replays | Expand edge case and wording coverage while keeping sensitive values out of test records. | Validate diversity, intent and labels against independent evidence. Watch generator bias, cue leakage, duplicates and reidentification risk. Use qualified adjudication for disputed labels. |
| Multimodal and long-context evaluation | Check images, attached documents, audio and speech against independent observations. Test cross-modal fact consistency and whether long-context evidence is retrieved, located and attributed. | Perturb evidence position, track citation support and verify whose memory was used. A fluent summary cannot establish that all evidence was read or combined appropriately. |
| Controlled and counterfactual evaluation | Change one fact, pair cases and test stable and responsive behavior. | Correlation cannot identify the cause of a score change. Blended interventions, shared examples and altered labels confound causal conclusions. Test sensitivity to assumptions. |
| Continuous evaluation and living benchmarks | Replay anchors, refresh held-out cases, and turn redacted incident evidence into regression tests. | Track changes in traffic, policy, model and judge separately. Version every benchmark refresh and keep old results. A moving dataset can make raw scores incomparable. |

For a paper-based judge example, Lianmin Zheng and colleagues study LLM judges against human preferences and report position, verbosity and self-enhancement biases. Use it to ask what the comparison measures and whether a proposed deployment needs stricter evidence than preference agreement. ## Research Evidence Checklist

Use source type as a clue about what to verify. A peer-reviewed paper has a review record. A preprint may be earlier and easier to revise. Technical reports often give implementation details, while vendor documentation establishes intended interfaces and versions. A leaderboard reports scores under its published protocol. Blogs can surface hypotheses and failure reports, and code repositories can reveal implementation or licensing details. Independent replications test whether conclusions hold under other conditions. Check artifacts, labels, assumptions and incentives for each source.

| Evidence worksheet field | Record before relying on a claim |
| --- | --- |
| Citation and provenance | Exact title, authors, affiliations, venue or source, publication date, version, disclosures and conflicts of interest |
| Target and construct | Research question, hypothesis, intended users, outcome definition, metric and operational value |
| Comparison and controls | Current and simple baselines, shared cases, selection protocol, budgets, hyperparameter tuning and confound checks |
| Data and code availability | Dataset and code versions or access limits, expected outputs, runtime, license and holdout safeguards |
| Results and uncertainty | Counts and denominators, effect size, uncertainty, ablations, severe errors and slice coverage |
| Reproduction and later evidence | Your reproduction status, independent replication, errata, subsequent corrections and unresolved questions |
| Safety, ethics and applicability | Known limitations, affected people, authorization and privacy safeguards, and scope of any proposed pilot |

## From Research to a Production Decision

Start with a problem you can measure, such as costly human review or missed high-severity errors. Find credible methods, record their claims and baselines, then reproduce one small result. Validate the new method on frozen local cases and compare it with the current baseline and a simpler alternative. Check rare, severe and multilingual cases. Ask what breaks when a dependency is delayed, a policy changes or the method disagrees with the baseline.

Record expected cost, latency, dependencies, staffing and how much review the method adds or saves. **Promising research** motivates a test. **Reproduced evidence** confirms the computations for the original scope. **Validated local improvement** requires independent local cases and a fair baseline. **Production readiness** requires release controls, human ownership and monitoring evidence. In this lab PASS is a shadow-only recommendation. Review a pinned, redacted sample while the approved evaluator serves production. Keep the candidate without write authority. Monitor queue size, cost, latency, verified severe errors and drift. Pause after a critical miss or when evidence becomes untrustworthy. Restore the old routing if needed and add validated incident cases to the next version. [Release decisions, rollback and governance](#m13-t03)

Keep a research backlog grouped by problems such as judge validity, label cost, trajectory verification and drift. Record source, claim, decision owner, evidence status and a next review date. Look periodically at venue proceedings, project releases and replication reports relevant to that backlog. Prioritize high-impact gaps and small independent experiments. Revisit unresolved claims when evidence changes. Retire assumptions that no longer match current policies and document each method change.

## Knowledge Check

- Why can a reproduced result fail to replicate?
- If adaptive testing finds more privacy failures, what can you conclude about ordinary traffic?
- When do you report REVIEW instead of PASS for a shadow pilot?

## Knowledge Check Answers

- The original artifacts may reconstruct the numbers precisely while the effect changes on fresh cases. Examine differences in population, policy, label protocol and scope before attributing the result.
- It found more failures under the particular selection and budget. Estimate ordinary prevalence from a suitable probability-based sample with a justified analysis.
- Use REVIEW when a required observation, configuration, independent test, owner approval or validated stop plan is incomplete. A confirmed critical failure or an essential reproduction mismatch takes precedence and blocks.

## Common Mistakes

- Treating peer review or a leaderboard as sufficient production evidence. Recheck the construct, baseline and intended deployment.
- Treating correlated labels or synthetic variants as independent samples. Track case families and apply the design's assumptions.
- Reporting only gains. Include regressions, missing evidence, severe cases, budgets and the decision scope.
- Equating a passed reproduction or approved pilot with broad deployment readiness. Require independent local evidence and staged monitoring.
