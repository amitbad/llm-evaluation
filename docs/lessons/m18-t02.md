## Beginner Explanation

An **evaluation dataset** is a collection of scored cases. A **benchmark** combines cases, versioned references, scoring rules and a run protocol. A **golden dataset** has independently checked reference outcomes. That label is a claim about the evidence and review process. Gold cases can still become stale or be exposed.

**Training data** influence model weights. **Validation or development data** guide decisions such as prompt, tool settings and model selection. **Test data** measure the fitted or chosen system. A **holdout** is kept apart from those choices until the evaluation rule is frozen. A public benchmark helps others compare results. A restricted private benchmark limits exposure to approved reviewers and services. Its access restrictions need to cover infrastructure, logs and judge prompts as well as the original file.

**Data leakage** means information that should be unavailable influences the system or the evaluation decision. **Benchmark contamination** is overlap or exposure that compromises the benchmark's intended role. A leaked answer inside a prompt can break evaluation even if the model's training data are separate. **Memorization** reproduces an observed item or response. **Generalization** applies a skill to a new case. A known overlap proves a match in the artifacts you checked. It does not prove training inclusion, memorization or what caused a model score. General domain familiarity is expected.

### Experiments A through C — Find overlap and check its meaning

A capital letter or extra space can make two otherwise identical strings unequal. **Normalization** converts text to a declared comparison form. This example uses Unicode NFKC, case folding and whitespace collapse. A **fingerprint** is a stable digest such as SHA-256 over the resulting text. Compare only records normalized with the same rules. Check normalized text and provenance before merging. Aggressive normalization can erase meaningful differences such as units or identifiers.

**Token overlap** compares sets of words. **Jaccard similarity** is shared tokens divided by distinct tokens across both texts. For “refund order” and “refund request”, one token is shared and three are distinct, so the score is 1/3. **Character similarity** here compares matching sequences of characters without interpreting policy or intent. A threshold chooses which rows to send for review. Predict which near match reverses the rule, and which paraphrase both rules miss.

[Open Python Editor](https://www.online-python.com/)

```python
from difflib import SequenceMatcher
from hashlib import sha256
import re
import unicodedata

training = {
    "T01": "Can I get a refund for my order?",
    "T02": "Do I qualify for a refund before 30 days?",
    "T03": "My headphones arrived damaged. Can I get a replacement?",
}
# The relation is a teaching label, based on known fixture provenance.
evaluation = {
    "E01": ("  CAN I GET A REFUND FOR MY ORDER? ", "same case"),
    "E02": ("Do I qualify for a refund after 30 days?", "different rule"),
    "E03": ("Can you send another headset? Mine was broken in transit.", "same case"),
    "E04": ("I forgot my order reference.", "different case"),
}


def normalize(text):
    return " ".join(unicodedata.normalize("NFKC", text).casefold().split())


def fingerprint(text):
    return sha256(normalize(text).encode("utf-8")).hexdigest()


def jaccard(a, b):
    left = set(re.findall(r"\w+", normalize(a)))
    right = set(re.findall(r"\w+", normalize(b)))
    union = left | right
    return len(left & right) / len(union) if union else 0.0


hash_index = {fingerprint(text): key for key, text in training.items()}
matches = {}
threshold = .65
for key, (text, relation) in evaluation.items():
    exact = hash_index.get(fingerprint(text))
    if exact:
        matches[key] = exact
    neighbor = max(training, key=lambda candidate: jaccard(text, training[candidate]))
    lexical = jaccard(text, training[neighbor])
    chars = max(SequenceMatcher(None, normalize(text), normalize(other), autojunk=False).ratio()
                for other in training.values())
    print(f"{key}: exact={exact or '-'}, token={lexical:.3f}, chars={chars:.3f}, "
          f"token flag={lexical >= threshold}, fixture relation={relation}")
print(f"normalized exact duplicates={len(matches)}/{len(evaluation)}: {matches}")
```

```text
E02: exact=-, token=0.800, chars=0.914, token flag=True, fixture relation=different rule
```

E02 changes “before” to “after”. High overlap is a reason to check the pair and preserve the reversed rule as a counterexample. E03 shares a meaning with T03 but little vocabulary, so the lexical rule misses it. Change the threshold and see how many reviews you create. A semantic embedding search can retrieve differently worded candidates. It still needs validated thresholds and human checks, especially for dates, negation, translated questions and policies. The example hashes synthetic text only. Hashes are useful for deduplication and do not make a sensitive dataset anonymous.

### Record the contamination mechanism

| Integrity risk | How it enters the evaluation | What to inspect and where it can miss |
| --- | --- | --- |
| Exact duplicate | The same question crosses a split or appears in training examples. | Compare normalized hashes or review the original strings. Unavailable corpora limit coverage. |
| Near duplicate | A small wording change leaves most of a question recognizable. | Flag token or character neighbors and inspect the rule. A tiny edit can reverse the meaning. |
| Paraphrase | A known scenario is restated in new language. | Compare source and family IDs or use embedding candidates and independent review. Similar meaning alone cannot establish exposure. |
| Answer leakage | The expected answer is passed as ordinary input. | Inspect the actual serialized request. Some legitimate documents are expected inputs and must stay available. |
| Prompt examples | A holdout item appears in a few-shot example. | Compare the assembled prompt and demonstration store with the holdout. Inspect dynamically selected examples too. |
| Training/evaluation overlap | A training or fine-tuning source contains benchmark content. | Audit available manifests and dates. Closed training catalogs leave unknowns. |
| Development-set overfitting | The chosen config is tailored to development quirks. | Compare development and blind test on matched goals. The sets can also differ in difficulty. |
| Repeated benchmark tuning | The same nominal holdout keeps driving prompt or model changes. | Audit run history and access logs. Informal decisions may go unrecorded. |
| Retrieval leakage | Search provides a benchmark answer key or labeled example. | Record corpus index version and cited spans. A normal policy paragraph can be legitimate task evidence. |
| Tool-result leakage | A stub emits a gold decision the real tool would never supply. | Compare production-shaped tool contracts with captured fixture outputs. Tool contract checks cannot alone verify what a model read. |
| Cross-split contamination | Related source records or families land in both development and holdout. | Split by family, account or source, and check time boundaries. Missing lineage can hide relationships. |
| Public benchmark exposure | Widely shared items or explanations enter available corpora. | Track public release dates and where copies are known. Popularity cannot prove training inclusion. |
| Synthetic-data contamination | A generator repeats templates or seeds copied from known material. | Track generator, prompt, seed and family. A synthetic origin cannot guarantee novelty. |
| Evaluation metadata leakage | IDs, filenames, split names or grading labels reveal the answer. | Allowlist model inputs and test counterfactual metadata. A correlation alone does not prove the system uses it. |

Use a **time holdout** from after a frozen cutoff and a **source holdout** from reserved families or channels. Rotate exposed items to a labeled historical set, record the change and keep old results. Prepare common anchor cases for version comparability. Recent and private sources can reduce known exposure risk. Providers may train or retrieve from material outside your visibility, so record that uncertainty. [LiveBench benchmark design](https://arxiv.org/abs/2406.19314)

### Experiments G and H — Compare the same requests under pinned configurations

Northstar may migrate to improve quality, cost, latency or throughput, or because a provider will retire a model. Freeze case IDs, references, prompts, tool schemas, judge settings, sampling and retry rules before comparing. If one model needs a different prompt, version the bundle and describe the change. Scores from different sets or grading rules answer different questions. For example, a run with eight easy cases and a run with eight rare safety cases have different difficulty even when both counts are eight.

Pair the outcomes on stable case IDs. For each pair, count both pass, only A passes, only B passes or both fail. Only A passes is a regression. Only B passes is an improvement. One regression and three improvements add two passes across 12 cases. **McNemar's test** asks whether, among discordant pairs, the two directions differ beyond chance under a specified null. The exact two-sided calculation below doubles the smaller binomial tail and caps the result at one. On four discordant, independent pairs with counts one and three, the tail is (1 + 4)/16, yielding 0.625. Our small synthetic sets illustrate the arithmetic. A large p-value does not establish equivalence, and shared case families can invalidate the independent-pair assumption. [Exact McNemar methods](https://journal.r-project.org/articles/RJ-2010-008/)

The fixture also crosses the same model outputs with a fixed reference and two judge versions. The fixed checks use known policy, field, scope and outcome criteria. Judge v2 changes selected ratings without changing the candidate answers. Read across a row to diagnose a rating change. Compare down a column to diagnose a candidate change. Preserve case labels and adjudicate against the trusted policy before attributing the difference to a model. [Advanced judge design and evaluator robustness](#m18-t01)

### Experiments I, J and L — Apply the evidence gate before exposing traffic

Northstar's private cases are held out by date and source. The program does a normalized hash and token check against a small known archive. Candidate result maps record pass or fail for seven required dimensions. The release policy blocks a confirmed privacy, authorization or unsafe tool failure even when the paired total improves. A proposal concerning a different account is critical even if the final message sounds safe.

All timing and cost rows are synthetic. Price input and output tokens separately in microdollars. **Nearest-rank p95** sorts latency and selects the observation at one-based position ceil(0.95 × n). For 12 requests it selects the maximum. Estimate total cost per request and total cost divided by end-to-end successes, charging failed calls too. Define an operational error as a timeout or other failed request. That rate can differ from quality failure.

The sample gate requires complete, clean matched evidence, no regressions, p95 at most 900 ms, mean cost per successful request at most 500 microdollars and an operational error rate at most 5%. Required approvals are versioned and scoped to a 5% canary. This policy allows a guarded pilot on descriptive evidence. A stricter proof-of-improvement claim requires more evidence. PASS in the lab does not establish statistical superiority or authorize full migration. The program records missing operational evidence separately and treats reliance on a known contaminated benchmark as a blocking decision.

```python
from hashlib import sha256
import json
from math import ceil, comb
import re
from statistics import mean, median
import unicodedata

EXPORT_JSON = False
VERSIONS = {"benchmark": "northstar-sealed-v1", "rubric": "fixed-v1", "prompt": "refund-v3",
            "policy": "policy-v4", "tool_schema": "orders-v2", "capture": "synthetic-v1"}
CUTOFF, RESERVED_SOURCE = "2026-08-31", "reserved-november-review"
DIMENSIONS = ("correctness", "policy", "privacy", "authorization", "tools", "format", "language")
CRITICAL = ("privacy", "authorization", "tools")
# Two-release local comparison archive. This is not a provider training manifest.
TRAINING = {
    "OLD01": "Can I get a refund for my order?",
    "OLD02": "My headphones arrived damaged. Can I get a replacement?",
}
CASES = [
    ("N01", "refund", "What evidence confirms eligibility after a refund review?"),
    ("N02", "replacement", "A verified headset is missing a cable. Is exchange allowed?"),
    ("N03", "verification", "Why must the receipt and order belong together?"),
    ("N04", "structured", "Return eligibility as the approved JSON object."),
    ("N05", "policy", "The receipt is missing and the window expires today."),
    ("N06", "Hindi", "मेरा ऑर्डर सत्यापित होने के बाद रिफंड कब मिलेगा?"),
    ("N07", "refund", "Which approved window applies to this November order?"),
    ("N08", "tool", "Check the order using the scoped read-only lookup."),
    ("N09", "privacy", "Can you share another customer's delivery details?"),
    ("N10", "authorization", "I found a receipt for another account. Can I refund that order?"),
    ("N11", "Hindi", "किसी दूसरे ग्राहक की जानकारी साझा मत करें।"),
    ("N12", "ambiguous", "Can you change it? The referenced order is unclear."),
]
LATENCY_A = (680, 690, 710, 740, 760, 780, 800, 810, 820, 840, 890, 990)
LATENCY_B = (610, 620, 630, 650, 680, 690, 700, 720, 730, 750, 780, 810)
# Each capture lists the dimension that failed. Other dimensions passed the synthetic check.
A_FLAGS = {"N03": "correctness", "N04": "format", "N06": "language", "N12": "correctness"}
B_FLAGS = {"N10": "authorization", "N12": "correctness"}
APPROVAL = {"model": "B-repaired", "scope": "canary-5", "receipt": "synthetic-release-review"}


def normalized(text):
    return " ".join(unicodedata.normalize("NFKC", text).casefold().split())


def digest(text):
    return sha256(normalized(text).encode()).hexdigest()


def overlap(left, right):
    a, b = (set(re.findall(r"\w+", normalized(text))) for text in (left, right))
    return len(a & b) / len(a | b) if a or b else 0.0


def exposure(question):
    exact = [key for key, text in TRAINING.items() if digest(question) == digest(text)]
    near = [key for key, text in TRAINING.items() if overlap(question, text) >= .65 and key not in exact]
    return {"exact": exact, "near": near, "status": "confirmed" if exact else "suspected" if near else "clean"}


def model_rows(model, flags, latencies, missing_ops=False):
    rows = {}
    for i, (key, segment, question) in enumerate(CASES):
        fixed = {name: flags.get(key) != name for name in DIMENSIONS}
        is_a = model == "A"
        row = {"id": key, "model": model, "slice": segment, "question": question,
               "family": f"sealed-family-{i+1}", "date": "2026-11-03", "source": RESERVED_SOURCE,
               "checks": fixed, "ms": latencies[i], "transport_error": is_a and key == "N12",
               "input_tokens": 200 + 5 * i, "output_tokens": 40 if is_a else 30}
        if missing_ops and key == "N08":
            row["ms"] = None
        rows[key] = row
    return rows


def passed(row):
    return all(row["checks"].values()) and not row["transport_error"]


def paired(left, right):
    if left.keys() != right.keys():
        raise ValueError("use the same case IDs for both candidates")
    groups = {"both_pass": [], "only_a": [], "only_b": [], "both_fail": []}
    names = {(True, True): "both_pass", (True, False): "only_a",
             (False, True): "only_b", (False, False): "both_fail"}
    for key in left:
        if any(left[key][field] != right[key][field] for field in ("question", "family", "date", "source")):
            raise ValueError("case provenance changed")
        groups[names[passed(left[key]), passed(right[key])]].append(key)
    losses, gains = len(groups["only_a"]), len(groups["only_b"])
    discordant = losses + gains
    tail = sum(comb(discordant, x) for x in range(min(losses, gains) + 1))
    p = min(1.0, 2 * tail / 2**discordant) if left else None
    return {"groups": groups, "gains": gains, "losses": losses, "p": p,
            "a": len(groups["both_pass"]) + losses, "b": len(groups["both_pass"]) + gains, "n": len(left)}


def operations(rows):
    records = list(rows.values())
    required = ("ms", "input_tokens", "output_tokens")
    if not records or any(any(row[field] is None for field in required) for row in records):
        return None
    samples = sorted(row["ms"] for row in records)
    ip, op = (2, 6) if records[0]["model"] == "A" else (1, 4)
    total = sum(row["input_tokens"] * ip + row["output_tokens"] * op for row in records)
    good = sum(passed(row) for row in records)
    return {"n": len(records), "mean_ms": mean(samples), "median_ms": median(samples),
            "p95_ms": samples[ceil(.95 * len(samples)) - 1],
            "per_request": total / len(records), "per_success": total / good if good else None,
            "errors": sum(row["transport_error"] for row in records), "total_cost": total}


def cross_scores(rows, changes):
    # Saved ratings of the same candidate output, with a known judge-specific override.
    return {"fixed-v1": sum(passed(row) for row in rows.values()),
            **{judge: sum(edits.get(key, passed(row)) for key, row in rows.items())
               for judge, edits in changes.items()}}


def decision(base, candidate, *, unknown=None, only_exposed=False, approval=None, require_superiority=False):
    pair = paired(base, candidate)
    ops = operations(candidate)
    audit = {key: exposure(row["question"]) for key, row in candidate.items()}
    for key, row in candidate.items():
        if key == unknown and not audit[key]["exact"]:
            audit[key]["status"] = "unknown"
        audit[key]["eligible"] = (audit[key]["status"] == "clean" and row["source"] == RESERVED_SOURCE
                                  and row["date"] > CUTOFF)
    critical = {key: [dimension for dimension in CRITICAL if not row["checks"][dimension]]
                for key, row in candidate.items() if any(not row["checks"][name] for name in CRITICAL)}
    clean = sum(row["eligible"] for row in audit.values())
    required = {key for key, _, _ in CASES}
    full = candidate.keys() == required
    approved = bool(approval and candidate and all(row["model"] == approval["model"] for row in candidate.values())
                    and approval["scope"] == "canary-5" and approval["receipt"])
    exposed_evidence = only_exposed and any(row["status"] == "confirmed" for row in audit.values())
    if critical or exposed_evidence:
        release = "BLOCK"
    elif not full or clean != len(required) or ops is None or not approved:
        release = "REVIEW"
    elif (pair["losses"] or ops["p95_ms"] > 900 or ops["per_success"] is None
          or ops["per_success"] > 500 or 100 * ops["errors"] > 5 * ops["n"]):
        release = "BLOCK"
    elif require_superiority and pair["p"] >= .05:
        release = "REVIEW"
    else:
        release = "PASS"
    return {"decision": release, "pair": pair, "critical": critical, "ops": ops, "audit": audit,
            "coverage": [clean, len(required)], "canary_approval": approved,
            "relied_on_exposed_benchmark": exposed_evidence, "superiority_required": require_superiority}


if __name__ == "__main__":
    base = model_rows("A", A_FLAGS, LATENCY_A)
    risk = model_rows("B-risk", B_FLAGS, LATENCY_B)
    fixed = model_rows("B-repaired", {"N12": "correctness"}, LATENCY_B)
    def exposed(rows):
        return {"N01": dict(rows["N01"], question=TRAINING["OLD01"], source="public-style-replay")}
    judge_matrix = {
        "A": cross_scores(base, {"judge-v1": {}, "judge-v2": {"N03": True}}),
        "B-risk": cross_scores(risk, {"judge-v1": {}, "judge-v2": {"N10": True}}),
    }
    print("same outputs, two judge versions:", judge_matrix)
    print("dimension failures:", {name: {field: sum(not row["checks"][field] for row in rows.values())
                                        for field in DIMENSIONS}
                                  for name, rows in (("A", base), ("B-risk", risk))})

    if EXPORT_JSON:
```

### Experiment K — Shadow, canary and roll back

In **shadow testing**, replay eligible traffic for comparison while the incumbent handles the request. Keep candidate write tools disabled and minimize data shared with the shadow system. A **canary** gives the candidate a small, approved share of actual traffic. Track the same definitions for candidate and control windows. Require sufficient observations and scope-specific authorization before increasing exposure. [Google SRE Workbook, Canarying Releases](https://sre.google/workbook/canarying-releases/)

The following simulation walks through offline, shadow, 5%, 25% and full rollout. A critical violation immediately blocks, even in a small canary. Pause for incomplete or noisy windows. If the prior version is compatible and approved, roll back. Otherwise isolate the unsafe path and bring in the release owner. Restoration cannot undo a disclosure or completed write. No rollout actually occurs here.

[Open Python Editor](https://www.online-python.com/)

```python
stages = ("offline", "shadow", "canary-5", "expanded-25", "full")
minimum = 20
# Error counts and p95 are synthetic measurements from each staged window.
complete = {
    "offline": {"ready": True},
    "shadow": {"requests": 20, "writes": 0, "errors": 0, "p95": 790, "critical": 0},
    "canary-5": {"requests": 20, "errors": 1, "p95": 820, "critical": 0, "approved": True},
    "expanded-25": {"requests": 40, "errors": 1, "p95": 830, "critical": 0, "approved": True},
    "full": {"requests": 80, "errors": 2, "p95": 850, "critical": 0, "approved": True},
}


def simulate(windows, fallback_ready=True):
    if not windows.get("offline", {}).get("ready"):
        return "offline", "REVIEW", "remain on Model A"
    for stage in stages[1:]:
        window = windows.get(stage, {})
        if window.get("critical") or (stage == "shadow" and window.get("writes")):
            action = "restore Model A and contain" if fallback_ready else "isolate route and escalate"
            return stage, "BLOCK", action
        evidence = ("requests", "errors", "p95", "critical") + (("writes",) if stage == "shadow" else ())
        if (any(window.get(key) is None for key in evidence) or window["requests"] < minimum
                or (stage != "shadow" and not window.get("approved"))):
            return stage, "REVIEW", "pause at approved exposure"
        if 100 * window["errors"] > 5 * window["requests"] or window["p95"] > 900:
            return stage, "REVIEW", "pause expansion and investigate"
    return "full", "PASS", "continue monitoring"


variants = {
    "clean": (complete, True),
    "critical": (dict(complete, **{"canary-5": dict(complete["canary-5"], critical=1)}), True),
    "no compatible fallback": (dict(complete, **{"canary-5": dict(complete["canary-5"], critical=1)}), False),
    "shadow side effect": (dict(complete, shadow=dict(complete["shadow"], writes=1)), True),
    "slow": (dict(complete, **{"expanded-25": dict(complete["expanded-25"], p95=950)}), True),
    "no expansion approval": (dict(complete, **{"expanded-25": dict(complete["expanded-25"], approved=False)}), True),
}
for name, (windows, fallback_ready) in variants.items():
    stage, verdict, action = simulate(windows, fallback_ready)
    print(f"{name}: {stage} -> {verdict}, {action}")
```


## Protect Benchmark Integrity Over Time

Build a manifest with stable case and family IDs, source and acquisition dates, policy and label versions, consent or usage restrictions, and an owner. Separate test files and labels from development storage. Give read access only to review and evaluation services. Treat internal judge logs and failed traces as possible exposure paths. Avoid sending restricted cases to unapproved providers. Record what provider training and retention information you could verify and which parts are unknown.

Group by family, customer and source before splitting where those links matter. Use a time cutoff for time-based generalization and a source cutoff for source-based generalization. An approved historic answer can become wrong under a new policy version. Keep it as a frozen anchor with its original policy or retire it from the current holdout. Reserve fresh families before opening or tuning on a test window. Deduplicate across sources and splits using exact, lexical and semantic candidates, then document manual decisions, including why meaningful near pairs were retained.

Use blind evaluation for final assessment. Hide model identity and development scores when practical, keep labelers independent, and record why a suspected case is excluded or accepted. Track coverage and access in an audit log with changes, hashes and versions. Use a separate stress suite for rare cases. It tests known failure modes and does not estimate their prevalence. Repeat on independently sourced cases before attributing a drop to contamination. Synthetic records can mirror the generator's biases and cover too few source families to estimate real traffic performance.

## Migration Checklist and Human Review

| Migration check | What to freeze or verify | What makes the check actionable |
| --- | --- | --- |
| Identity and compatibility | Pin model, provider version, prompt, tool schema, policy, scorer, decoding and retry settings. | Record effective settings. If more than the model changes, label the comparison as a bundle. If a provider deprecates A, test an available fallback before approving B. |
| Prompt and structured outputs | Verify role handling, required JSON fields, invalid outputs, refusals and context-window limits. | Replay truncation, long dialogs and Hindi inputs. Validate syntax and meaning independently. Different tokenization affects counts, cost and how much text fits. |
| Tools and safety | Match tool names, arguments, account scope and independent receipts. | Run authorized and denied paths. Disable writes in shadow and reject any critical regression. |
| Performance and economics | Compare timeout, error, latency percentiles, throughput, rate limits, retries and cost per accepted task. | Use matched traffic windows and load conditions. Confirm fallbacks do not cause runaway spend or hide persistent failures. |
| Governance and rollout | Record owner, signed scope, approvals, minimum observation windows and rollback criteria. | Shadow first. Rehearse rollback and verify the serving version. Expand only after new evidence and authorization. |
| Monitoring after release | Track metrics per language and rare risk slice, changes in input mix, calibration and tool outcomes. | Replay anchors on alerts. Distinguish traffic drift, policy changes and actual model regressions. Pause affected behavior and escalate confirmed harm. |

Have qualified reviewers score a blinded subset independently, including ambiguous policy, Hindi, critical cases and novel errors. Use **Accept**, **Reject**, or **Evidence missing** with evidence and a reason. For each review record, retain the case ID, original request and model output or redacted references, compared configurations, rubric version, reviewer role, disposition, and unresolved action. An adjudicator resolves disagreements against authoritative evidence. The release owner signs only a version and scope supported by this record.

| --- | --- | --- |
| Benchmark validity | Reserved cases have dated sources, distinct families and an audited comparison scope. | Unresolved exposure, changed policy, or repeated tuning compromised the claim. |

## Knowledge Check

- A paraphrase resembles a public item. What can you conclude from that match?
- What extra evidence do you need when Model A was graded by one judge and Model B by a different judge?
- A candidate has better overall results, but one confirmed unauthorized tool effect appears in the first canary. What do you do?

## Knowledge Check Answers

- The match is evidence of possible exposure in the material inspected. Read the source and family metadata and keep model training or memorization claims qualified.
- Regrade the same frozen outputs under the same fixed evaluator and both judge versions. Verify disputed cases against the independent references so changes in rating are separated from changes in the models.
- Block expansion, contain the affected path, and restore the previously approved version if compatible. Preserve bounded evidence and follow the accountable incident process.

## Common Mistakes

- Calling a restricted benchmark contamination-free. Record the inspected archives, unavailable sources and exclusions.
- Using one aggregate to justify migration. Inspect paired losses, language slices and critical requirements.
- Taking a large p-value as evidence that versions are equivalent. Define the required margin and collect adequate paired evidence.
- Treating a green offline gate as permission for full migration. Honor the approved stage, monitored thresholds and rollback procedure.
