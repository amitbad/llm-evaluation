## Beginner Explanation

### 1. Check which customers your sample represents

Suppose ten customer questions arrive. Eight are ordinary fee questions and two ask about the cutoff. If you read five questions and all five are ordinary lookups, you have learned how the assistant handled those five. A **sample** is a subset you examine. A **representative sample** should resemble the population you want to describe on the characteristics that matter. Here the population is the set of eligible questions in the time window you picked.

Write down a target of four ordinary questions and one cutoff question before reading any answers. Four out of five is 80% and one out of five is 20%, the same mix as eight and two out of ten. Put the eligible IDs into two piles and draw from each pile. This is **stratified sampling**, and each pile is a **stratum**. Draw without checking which cases passed. If all five selected cases still come from one date or account, report that limitation alongside the matched proportions.

### 2. Check hard cases more often for a different decision

One sampled cutoff question is easy to miss. Suppose an audit asks you to check four ordinary cases and four cutoff cases. In that audit half the cases are cutoff questions, compared with two in ten in the target traffic. Deliberately including more cases from a rare group is **oversampling**. A **stress set** is an evaluation set designed to probe difficult or high-consequence cases.

For the new assistant in the opening example, all eight ordinary answers passed, and one of two cutoff answers passed. Imagine applying those same group rates to a different mix. In ten cases with the everyday mix, you would expect eight ordinary passes and one cutoff pass, or nine of ten. In an eight-case stress mix with four of each, the same rates would give four ordinary passes and two cutoff passes, or six of eight. The group rates stayed fixed in this calculation. Only how much each group contributes to the overall score changed.

This stress mix gives cutoff failures more influence. Report the stress score under its own name. For an estimate of everyday performance, use a representative sample or trustworthy group rates combined using the actual traffic proportions. With only two cutoff observations, the true rate for that group is still uncertain.

Try changing just one important detail, such as the balance from ₹4,999 to ₹5,000. An **adversarial edge case** here is a deliberately difficult test chosen to surface a likely error. The bank could set a practice requirement before testing. Include at least one verified exact-minimum case and pause release if any such case applies a charge. A reviewer still needs to verify each label against the policy. Passing the small set answers that release check and gives little evidence about rare failures outside it.

### 3. Protect questions used for the final check

A team can use some saved questions to improve its prompts or examples. Call those its **development set**. Reserve a separate set for checking how those changes work on unseen cases. That set is a **holdout**. If you tune using answers from the holdout, the final score can reward familiarity with that material. This is **leakage**, a form of train/test contamination. It can happen during prompt tuning or case selection even when no model weights are changed.

Consider “Do I pay a fee at ₹5,000?” and “Is there a charge at the ₹5,000 minimum?” If both were made from the same fee guide, you could put them in different sets by mistake. Group cases by the policy or document family that links them. Give the whole family one destination. This is a **grouped split**. Preserve the source and family IDs so someone else can verify which cases travelled together.

Put “What fee applies below ₹5,000?” beside “What fee applies above ₹5,000?” If you remove the second just because most words match, you lose a useful check. Now put two paraphrases of the exact same question side by side. Keeping both as separate cases can double the weight of one underlying test. **Deduplication** means finding repeated material and deciding whether to keep one copy or group related cases. Use similarity to flag pairs, then read both questions and their sources before deciding. Settle the family assignments before drawing samples for each side. If the available families leave a gap in coverage, report the gap and find suitable data.

### 4. Refresh the evaluation when policy changes

For this chapter, SV-2#2 sets the July Standard Savings minimum at ₹5,000. A ₹100 monthly fee applies below it. Imagine the bank approves a new fee guide, SV-3#2, for August 1, 2026 onward. Its minimum is ₹6,000 and its fee is ₹120 per month below that balance. Both are fictional policy excerpts for this lesson.

Keep the frozen July holdout and its results. A question explicitly about July can still be correct as a historical case. If you’re checking the current policy, move July-only coverage out of that current check and keep it in the historical set. This is **retirement** from a specific evaluation. Add reviewed August cases in a new version. This is a **refresh**. Record the parent version, additions and retirements, their reasons, and who can see the new holdout.

For this unseen-family check, give developers practice cases from other families. Keep the reserved guide, questions, labels, and close variants behind the review boundary. If developers need the August guide for tuning, record that use and reserve a different family for an unseen-family check. Preserve the old benchmark so you can replay it. A split check can catch some paths for leakage. You still need access controls and a record of what was actually used to tune.

```python
import json


def audit(rows, source_families):
    groups = {"development": set(), "holdout": set()}
    seen = set()
    errors = []
    for row in rows:
        case_id = row["id"]
        if case_id in seen:
            errors.append("Duplicate ID: " + case_id)
        seen.add(case_id)
        side = row["split"]
        if side not in groups:
            errors.append("Unknown split: " + side)
            continue
        family = source_families.get(row["source"])
        if family is None:
            errors.append("Unknown source: " + row["source"])
            continue
        groups[side].add(family)
    for family in sorted(groups["development"] & groups["holdout"]):
        errors.append("Shared family: " + family)
    return errors


sources = {"ST-1#1": "statements", "SV-2#2": "fee-guide", "SV-3#2": "fee-guide"}
frozen = [
    {"id": "D-01", "split": "development", "source": "ST-1#1",
     "question": "What format are monthly statements available in?", "expected": "PDF"},
    {"id": "H-01", "split": "holdout", "source": "SV-2#2",
     "question": "Is a fee due at 5000 on July 15, 2026?", "expected": "NO_FEE"},
]
candidate = {
    "id": "H-03", "split": "holdout", "source": "SV-3#2",
    "question": "Is a fee due at 6000 on August 1, 2026?", "expected": "NO_FEE",
}
proposed = frozen + [candidate]

print("Frozen v1 rows:", len(frozen))
errors = audit(proposed, sources)
if errors:
    for error in errors:
        print(error)
    print("HOLD: do not use draft split")
else:
    manifest = {
        "version": "fees-v2-draft", "parent": "fees-v1",
        "added": [candidate["id"]], "holdout_access": "reviewer-only",
        "scope": "July history and August review reported separately",
    }
    print("Manifest:", json.dumps(manifest))
    for row in proposed:
        print(json.dumps(row))
```

## Common Mistakes

- **Treating a convenient sample as typical.** Record the question mix and how you selected within groups.
- **Comparing aggregate scores under different weights.** Compare like with like and show the difficult group.
- **Removing near-duplicates by score alone.** Read the full meaning and evidence before merging or grouping.
- **Reshuffling an exposed family.** Save the exposure history and reserve truly unexposed material.
- **Updating a frozen set in place.** Preserve the previous benchmark and explain the refresh or retirement in a new version.
