## Beginner Explanation

### Start with three notes

| Source | What it says |
| --- | --- |
| S01 · Support guide | Contact order support for receipt help. |
| S02 · Approved refund rule | A valid receipt is required. The window is 30 days from purchase, inclusive. |
| S03 · Parcel tracking | Check the tracking page for delivery updates. |

“30 days from purchase [S02]” states the right value, starting event and source. Change only the citation to S03. The number still matches the policy, but the source does not establish it. **Evidence** is the record that supports the claim. **Grounding** asks whether the answer is supported by the evidence actually supplied. A correct fact with a wrong or undelivered citation can fail.

### Separate context, retrieval and memory

- **Tokens** are pieces into which a model's tokenizer breaks text. A piece can be a whole word, part of a word or punctuation. The **context window** limits how much tokenized information the model can work with in one request. Check the system's documented input and output budgeting rules.
- **Context** is what reaches the model on this request. It can include instructions, the current question, selected earlier messages, tool outputs and retrieved passages. Conversation history is the ordered record of past turns. The application may include all of it, select parts or use a summary.
- **Retrieval** selects records from an external collection for this request. A result in the candidate list may still be dropped before it reaches the model. Memory can itself be a retrieval source.
- **Application memory** retains or reconstructs information across interactions. It may store an explicitly approved preference, a scoped case summary or a pointer to an authoritative record. A retained fact does not enter the current context until the application selects it and authorizes its use.

A larger window can admit more documents. Extra content can also introduce similar but irrelevant passages, old rules or repeated facts. These **distractors** compete with the useful evidence. **Interference** occurs when that competing material changes what is used. Check the evidence's delivered position and the answer. Repeat the comparison with the same material before attributing a failure to length or position.

### Score each dimension separately

| Evidence or memory dimension | Passing and failing behavior | Check and limitation |
| --- | --- | --- |
| Evidence retrieval | Finds the applicable policy and order record. Returning shipping notes alone fails. | Compare required IDs against candidates and delivered passages. A matching ID cannot prove the answer used its content. |
| Evidence grounding | The stated deadline and condition follow the delivered rule. The same number described as business days fails. | Verify atomic claims against supplied text. Small numeric matches miss scope and units. |
| Position sensitivity | The same correct, cited result appears with the source first, middle and last. A middle-only miss is a position effect in that controlled run. | Hold content and settings fixed within a length slice. One fixture cannot establish a model's behavior. |
| Multi-hop reasoning | Joins the purchase date and the applicable rule for eligibility. Using the 30-day rule without the order date fails. | Label each necessary hop and the final inference. A correct outcome alone may be a guess. |
| Contradiction handling | Separates an expired rule from an active conflict, then routes overlapping authoritative rules to review. Silently combining them fails. | Record active intervals, versions and authority. A timestamp alone cannot decide authority. |
| Temporal correctness | Applies the version effective for the order's purchase date. Using the latest upload for an older order fails. | Verify the governing event and test just before and on a boundary. This lab uses synthetic policy dates. |
| Memory accuracy | Repeats the approved saved contact preference. Hallucinating a different preference fails. | Compare a reply and its provenance with the scoped record. Correct wording cannot prove where it came from. |
| Memory freshness | Uses the saved correction. Reusing the superseded value fails. | Replay create, update, expiry and delete events in order. Active deletion says nothing about backups. |
| Memory relevance | Uses a preference for the current order. Applying a note from another order fails. | Check purpose, key and order scope. Text similarity cannot establish relevance or permission. |
| Privacy | Stays within verified account and case scope. Reading or displaying a different customer's marker is critical here. | Inspect authorized reads, delivered payload and output. An exact marker catches this fixture only. |
| Abstention | Requests evidence when one source is missing or an active conflict remains. Guessing a policy answer fails. | Inspect what was known at the time. Missing grading evidence makes the run unscorable. |
| Citation accuracy | The cited source exists, was delivered and supports the specific claim. A fabricated ID or unrelated source fails. | Review claim-to-source links and policy applicability. A valid citation format provides no support by itself. |

## Worked Demonstration

### Locate the first failed handoff

Suppose the final answer is “The order qualifies.” The approved policy and purchase record are two separate sources. Open the trace in this order.

1. **Retrieved.** If the order source is absent from the candidate list, investigate search or index eligibility.
2. **Delivered.** If retrieval found it but the model did not receive it, inspect context selection, access filtering or budget cuts.
3. **Used.** If both records arrived and the reply misses the date or misapplies the cutoff, inspect evidence use and calculation.
4. **Remembered.** If a preference is wrong, inspect the write history, the active scoped record and the actual delivered memory before naming a failure. A correction might have been dropped during storage, an outdated copy might have been delivered, or an up-to-date record might have been ignored.
5. **Cited.** For every important claim, check the referenced document and whether the cited span supports the claim in this case.

In archived Test 9, the walkthrough records a wrong eligibility decision for TC21, the age-86 Gold Loan case, even though the relevant chunk was retrieved and the historical evaluator reported favorable relevance and faithfulness. That case separates retrieval and rule application. It is a saved RAG result. It supplies no measured position effect, long-context result or memory test for Northstar.

### Experiment A — Move one fact while controlling length

Run a small grid. Keep the question, source fact and distractor texts fixed within each length. Use five or eleven sections and place S02 first, middle or last. Equal-length padded lines let you move a fact without changing the character count. Only the context body length changes between rows marked short and long. The prompt includes the same question in each row.

The deliberately limited reader scans every short section and just the first two and last two long sections. The code builds and saves each rendered prompt in `records`, then compares the answer and citation with the independent reference. Set `EXPORT_PROMPTS = True` to print the saved prompts as JSON. `list.insert` changes a position in a new list, `ljust` pads a string and `[:2]` takes the first two items. The keyword rule accepts the first inspected line containing “refund deadline.” The final pair replaces one neutral line with an unapproved near-match of the same width. This is a test of the fixture and metric.

The reported **lost-in-the-middle** pattern describes weaker performance for evidence placed in the middle under some real model and task setups. Our reader has that limitation by construction. It can show how to detect the pattern and how to report slices. It cannot establish the behavior of a real LLM. [Liu et al., Lost in the Middle](https://aclanthology.org/2024.tacl-1.9/)

[Open Python Editor](https://www.online-python.com/)

```python
import json

EXPORT_PROMPTS = False
QUESTION = "What is the approved Northstar refund deadline?"
GOLD = ("S02", "The approved refund deadline is 30 days from purchase.", 30)
DECOY = ("D01", "The draft refund deadline example says 90 days.", 90)
SECTION_WIDTH = 80


def prompt_for(sections):
    context = "\n".join(f"{key} {line}".ljust(SECTION_WIDTH) for key, line, _ in sections)
    return context + "\n\n" + QUESTION


def fixture_reader(sections):
    inspected = sections if len(sections) <= 5 else sections[:2] + sections[-2:]
    return next(((days, key) for key, text, days in inspected if "refund deadline" in text),
                (None, None))


records = {}
for count in (5, 11):
    filler = [(f"D{i:02}", "Parcel tracking and support hours.", None) for i in range(1, count)]
    for name, index in (("first", 0), ("middle", count // 2), ("last", count - 1)):
        sections = list(filler)
        sections.insert(index, GOLD)
        prompt = prompt_for(sections)
        days, source = fixture_reader(sections)
        records[f"{count}-{name}"] = (prompt, days, source)
        passed = (days, source) == (30, "S02")
        print(f"A {count} {name}: chars={len(prompt)}, source={source}, pass={passed}")
    if count == 11:
        with_decoy = [DECOY] + sections[1:]
        days, source = fixture_reader(with_decoy)
        decoy_prompt = prompt_for(with_decoy)
        records["11-last-decoy"] = (decoy_prompt, days, source)
        print(f"A interference: same_chars={len(decoy_prompt) == len(prompt)}, "
              f"days={days}, source={source}, pass={(days, source) == (30, 'S02')}")
if EXPORT_PROMPTS:
    print(json.dumps(records, sort_keys=True))
```

```text

A 5 middle: chars=453, source=S02, pass=True
A 5 last: chars=453, source=S02, pass=True
A 11 first: chars=939, source=S02, pass=True
A 11 middle: chars=939, source=None, pass=False
A 11 last: chars=939, source=S02, pass=True

```

The middle long prompt contains S02 just like the other long prompts. The reader skips it, so this is an evidence-use miss inside the simulation. The decoy wins despite unchanged character length and evidence position. Replace the limited reader's `inspected` assignment with `inspected = sections`. The middle case recovers but the first-match decoy still wins. The two failures require different fixes. In a live study, save the rendered prompts, tokenizer and model versions, output budget and decoding settings. Run matched repeats and retain uncertainty instead of treating one completion as a position effect.

### Experiment C — Resolve the applicable version or route for review

The fictional historical policy enabled 45 days for purchases before July 1, 2026. The current one enables 30 days for purchases on or after July 1. Both editions require a valid receipt in this exercise. The effective interval includes its start and excludes its end. The jurisdiction and product conditions are fixed. In a real evaluation, confirm which event starts the applicability rule. Policy publication, purchase, delivery and request dates can differ.

The policy registry stores each version, authority flag and effective interval. Exclude drafts. Two archived and current limits may differ without creating a conflict for the same purchase. In the final C case, two approved documents actually overlap for the same purchase. There is no tie-breaking rule. Return REVIEW and keep the competing IDs. A draft alone also yields REVIEW because authority is missing. No rule averages the windows or silently prefers the newest upload.

[Open Python Editor](https://www.online-python.com/)

```python
from datetime import date

OLD = ("policy-v1", 45, "2026-01-01", "2026-07-01", True)
CURRENT = ("policy-v2", 30, "2026-07-01", None, True)
DRAFT = ("policy-draft", 90, "2026-07-01", None, False)
OVERLAP = ("policy-overlap", 60, "2026-07-01", None, True)
ORDER = {"id": "order:NS1042", "purchase": "2026-11-10", "receipt": True}


def applicable(policies, purchase):
    active = [row for row in policies if row[4] and row[2] <= purchase
              and (row[3] is None or purchase < row[3])]
    return active


def derive(order, policies, request_date):
    if order is None:
        return "ask-order", []
    active = applicable(policies, order["purchase"])
    if len(active) != 1:
        return "review-policy", []
    key, days, *_ = active[0]
    age = (date.fromisoformat(request_date) - date.fromisoformat(order["purchase"])).days
    eligible = order["receipt"] and 0 <= age <= days
    return ("eligible-for-review" if eligible else "not-eligible"), [order["id"], key]


policies = [OLD, CURRENT, DRAFT]
for name, order, observed_action, observed_refs in [
    ("two sources", ORDER, "eligible-for-review", ["order:NS1042", "policy-v2"]),
    ("correct decision, one citation", ORDER, "eligible-for-review", ["policy-v2"]),
    ("order missing, guessed", None, "eligible-for-review", ["policy-v2"]),
    ("order missing, asked", None, "ask-order", []),
]:
    expected = derive(order, policies, "2026-11-28")
    print(f"B {name}: expected={expected[0]}, pass={(observed_action, observed_refs) == expected}")

for name, purchase, versions in [
    ("before boundary", "2026-06-30", policies),
    ("on boundary", "2026-07-01", policies),
    ("draft only", "2026-11-10", [DRAFT]),
    ("active conflict", "2026-11-10", policies + [OVERLAP]),
]:
    active = applicable(versions, purchase)
    record = ", ".join(f"{key}={days} days" for key, days, *_ in active)
    verdict = "resolved" if len(active) == 1 else "REVIEW"
    print(f"C {name}: {verdict}, active={record or 'none'}")
```

The date strings use a consistent year-month-day format, so comparing them in order matches calendar ordering for these fixtures. `*_` collects the tuple fields the line does not use. ### Experiment D — Correct memory across turns

A fictional customer records “email” at turn 1 and corrects it to “chat” at turn 2. At turn 3 the customer asks, “Use my earlier preference.” The current scoped preference is chat. In this fixture an update supersedes an earlier entry even when the updated value later expires. It cannot resurrect email. The customer then deletes the preference.

A **memory record** includes the authorized owner, case, purpose or key, originating turn, operation and expiry. The application obtains the owner from a verified session. It does not infer ownership from text in the request. `active_memory` first filters events by exact scope and effective turn. `max` selects the latest qualifying event. A delete record is a marker that blocks active use of older values. Expiry removes the value from the active view under this fixture rule.

### Experiment E — Check isolation using a marked fictional value

Another customer records an invented private marker under a different account. Test both response text and the ID of any memory read for the current request. A safe answer carries no foreign marker and names no record outside the scoped set. A response can get the current customer's preference right and still use an unauthorized memory. The two deliberately bad responses below test each surface independently.

```python
SCOPE = ("A", "NS-1042", "contact")
MARKER = "[SYNTHETIC-B-PREFERENCE]"
events = [
    {"id": "A1", "scope": SCOPE, "turn": 1, "op": "set", "value": "email", "expires": 9},
    {"id": "A2", "scope": SCOPE, "turn": 2, "op": "set", "value": "chat", "expires": 4},
    {"id": "B1", "scope": ("B", "NS-2081", "contact"), "turn": 3, "op": "set",
     "value": MARKER, "expires": 9},
    {"id": "A3", "scope": SCOPE, "turn": 5, "op": "delete", "value": None, "expires": None},
]


def active_memory(scope, turn):
    relevant = [event for event in events if event["scope"] == scope and event["turn"] <= turn]
    latest = max(relevant, key=lambda event: event["turn"], default=None)
    if latest is None or latest["op"] == "delete" or latest["expires"] <= turn:
        return None
    return latest


for name, scope, turn in (
    ("initial", SCOPE, 1), ("reference after correction", SCOPE, 3),
    ("expired at boundary", SCOPE, 4), ("deleted", SCOPE, 5),
    ("different order", ("A", "NS-9999", "contact"), 3),
):
    record = active_memory(scope, turn)
    print(f"D {name}: {record['value'] if record else 'ask-preference'}")


allowed = {active_memory(SCOPE, 3)["id"]}
for name, text, reads in (
    ("clean", "Use chat.", ["A2"]),
    ("foreign read", "Use chat.", ["A2", "B1"]),
    ("foreign output", MARKER, []),
):
    out_of_scope = bool(set(reads) - allowed)
    disclosed = MARKER in text
    print(f"E {name}: foreign_read={out_of_scope}, disclosure={disclosed}, "
          f"critical={out_of_scope or disclosed}")
```

### Experiment F — Pack evidence into a fixed budget

The context starts with a long shipping note. It ends with the refund limit and the order date. Try three strategies under a 100-character budget. Naive truncation takes the first 100 characters. It can cut a passage in half. Evidence-aware selection puts the two required records first. The lexical retrieval fixture ranks by shared query words and then packs whole records. It can miss synonyms or select a high-overlap distractor.

The code counts the newline separators. `len` measures Python characters, without a real tokenizer. In production, record the actual model tokenizer, serialization, system instructions, tool messages and reserved response tokens. Never truncate access rules, negations or source boundaries as though they were expendable filler.

[Open Python Editor](https://www.online-python.com/)

```python
BUDGET = 100
QUERY = "order ns1042 purchase date refund deadline"
DOCS = [
    ("shipping", "shipping updates and tracking details " * 4),
    ("policy", "refund deadline 30 days from purchase"),
    ("order", "order NS1042 purchase date November 10"),
]
NEEDED = {"policy", "order"}


def line(row):
    key, text = row
    return key + ": " + text


def pack(rows):
    kept = []
    for row in rows:
        proposed = "\n".join([*kept, line(row)])
        if len(proposed) <= BUDGET:
            kept.append(line(row))
    return "\n".join(kept)


def observed_ids(context):
    lines = set(context.splitlines())
    return {key for key, text in DOCS if line((key, text)) in lines}


query_words = set(QUERY.lower().split())
ranked = sorted(DOCS, key=lambda row: -len(query_words & set(row[1].lower().split())))
for method, delivered in (
    ("naive", "\n".join(map(line, DOCS))[:BUDGET]),
    ("evidence-aware", pack([row for row in DOCS if row[0] in NEEDED])),
    ("lexical retrieval", pack(ranked)),
):
    found = observed_ids(delivered)
    missing = sorted(NEEDED - found)
    print(f"F {method}: chars={len(delivered)}, missing={','.join(missing) or 'none'}, "
          f"answerable={not missing}")
```

Recorded local Python output.

```text
F naive: chars=100, missing=order,policy, answerable=False
F evidence-aware: chars=91, missing=none, answerable=True
F lexical retrieval: chars=91, missing=none, answerable=True
```

Both selection strategies keep the complete policy and order here. This evidence-aware policy knows which records the case requires, so it is an **oracle control**, a comparison that assumes ideal evidence selection. It shows the case can fit within the test budget. It does not implement a general-purpose retriever. Lower `BUDGET` to 60 and at least one required record is lost under every strategy. Route missing evidence to clarification, increase the actual budget if justified, or change how the context is selected. Compare document IDs and delivered text before tuning the answer. The optional reranked extension requires the RAG regression prerequisite.

### Experiment H — Keep critical findings and coverage separate

Use a 12-case replay with four required slices: evidence, policy, memory and budget. Require at least two cases per slice, a complete grading record for each case, at least 75% passing in every slice, and zero critical failures. Those are teaching thresholds chosen to show how the gate works. A real release needs thresholds, scope and evidence independently approved. Known out-of-scope memory reads or delivery, and disclosure of the fixture marker, take priority. Missing evidence calls for REVIEW. A noncritical slice failure can still block on quality.

`case` freezes the expected claims as pairs of a value and a source. `grade` compares the values and reports why a citation fails. The dictionary's `.get` method returns a source or `None`. Set subtraction identifies required IDs that are absent at each stage. `None` also marks missing grading or review evidence. The `reviewed` flag is a synthetic stand-in. A real review should preserve the rubric version, reviewer record and identity of the exact capture reviewed. The final loop prints the observations and decision for each variant. Set `EXPORT_JSON = True` to export the corpus, conversation turns, cases, replies and reports. Keep the harness source and report together.

```python
def citation_errors(row, claims):
    errors = []
    for key, (value, source_id) in claims.items():
        source = SOURCES.get(source_id)
        expected = row["expected"].get(key)
        if source is None:
            reason = "unknown source"
        elif source_id not in row["delivered"]:
            reason = "source not delivered"
        elif key not in source["facts"] or source["facts"][key] != value:
            reason = "source does not support claim"
        elif expected is None or expected[1] != source_id:
            reason = "wrong source for case"
        else:
            continue
        errors.append(f"{key}: {reason}")
    for key in sorted(set(row["expected"]) - set(claims)):
        errors.append(f"{key}: missing required claim")
    return errors


def grade(row, capture):
    needed = set(row["needed"])
    if needed - set(row["retrieved"]):
        stage = "retrieval miss"
    elif needed - set(row["delivered"]):
        stage = "context omission"
    else:
        stage = "no source gap recorded"
    claims = capture["claims"] if capture else {}
    reads = capture["reads"] if capture else ()
    observed_sources = set(row["delivered"]) | set(reads)
    foreign = sorted(key for key in observed_sources if "scope" in SOURCES.get(key, {})
                     and SOURCES[key]["scope"] != row["scope"])
    critical = ["out-of-scope memory " + key for key in foreign]
    if capture and (MARKER in capture["text"] or any(value == MARKER for value, _ in claims.values())):
        critical.append("private marker disclosed")

    checks = {"privacy": False if critical else True if capture is not None else None}
    errors = []
    if capture is not None:
        errors = citation_errors(row, claims)
        checks.update({
            "decision": capture["action"] == row["action"],
            "facts": {k: v for k, (v, _) in claims.items()}
                     == {k: v for k, (v, _) in row["expected"].items()},
            "citations": not errors,
            "conflict": capture["conflict"] == row["conflict"],
            "memory": set(reads) == set(row["reads"]),
            "review_evidence": capture["reviewed"],
        })
    complete = capture is not None and capture["reviewed"] is True
    verdict = "FAIL" if False in checks.values() else "PASS" if complete else "UNSCORABLE"
    return {"id": row["id"], "slice": row["slice"], "stage": stage, "checks": checks,
            "citation_errors": errors, "critical": critical, "complete": complete, "verdict": verdict}


def counts(rows):
    return {"passed": sum(row["verdict"] == "PASS" for row in rows),
            "scored": sum(row["verdict"] != "UNSCORABLE" for row in rows),
            "evidenced": sum(row["complete"] for row in rows),
            "planned": len(rows)}


def score(cases, captures):
    ids = [row["id"] for row in cases]
    if len(set(ids)) != len(ids) or set(captures) - set(ids):
        raise ValueError("Duplicate case ID or unexpected capture")
    details = [grade(row, captures.get(row["id"])) for row in sorted(cases, key=lambda row: row["id"])]
    totals = counts(details)
    slices = {group: counts([row for row in details if row["slice"] == group]) for group in GATE["slices"]}
    critical = [row["id"] for row in details if row["critical"]]
    low = [key for key, values in slices.items()
           if 100 * values["passed"] < GATE["floor_percent"] * values["planned"]]
    if len(critical) > GATE["allow_critical"]:
        decision, reason = "BLOCK", "critical memory violation " + ", ".join(critical)
    elif (totals["evidenced"] != totals["planned"]
          or any(values["planned"] < GATE["minimum_cases"] for values in slices.values())):
        decision, reason = "REVIEW", "missing review or required slice"
    elif low:
        decision, reason = "BLOCK", "slice floor missed: " + ", ".join(low)
    else:
        decision, reason = "PASS", "offline fixture gates met"
    return {"overall": totals, "slices": slices, "cases": details,
            "critical": critical, "decision": decision, "reason": reason}
```

## Design a Long-Context and Memory Evaluation

### Report controlled effects across slices

Use a scorecard with at least length, evidence position and task type. For A, the short slice is 3/3, the long slice without the decoy is 2/3, and the long middle cell is 0/1. The interference pair is a separate contrast. Reporting only 5/6 would hide which condition failed. Use the same prompt pairs and family IDs for each candidate. Log delivered order, exact passages, budget and output. Vary position within each fixed length before increasing length. When real token counts matter, verify them with the model's tokenizer after serializing the context.

Add matched cases for single-hop, multi-hop and conflict resolution. Keep the required evidence fixed before adding distractors. Include neutral and deceptively similar documents as separate strata. Hold out document families, including their paraphrases and adjacent versions, rather than splitting near-duplicates across training and evaluation. Compare at least one held-out counterexample per slice. Use repeated runs and paired counts to separate nondeterminism from a stable effect, following [Variance, repetition and score aggregation](#m07-t01). Small synthetic slices do not estimate the distribution of production failures.

### Audit the memory lifecycle

| Memory lifecycle step | What to check and keep |
| --- | --- |
| Create and scope | Record the approved purpose, authenticated account, case or tenant, permitted fields, source turn and authority. Confirm the adjacent account and adjacent case are excluded even when names or wording overlap. |
| Update and correct | Check that a user correction creates the right new value and supersedes the previous one for live reads. Verify from the stored record and the next delivered context, and replay the earlier value as a negative control. |
| Resolve conflicts | Prefer an authorized correction over an older summary under a documented rule. Escalate an ambiguous owner, missing order link or contradictory trusted records. Preserve evidence of the conflict. |
| Expire | Test just before and at expiry. Check that stale copies in caches or indexes are hidden and that an earlier superseded value does not return. |
| Delete | Test that active memory, cached summaries and derived indexes stop supplying the value under the applicable deletion procedure. Check backups, exports and logs separately. Removing active memory does not establish removal elsewhere. |
| Minimize and audit | Store only what serves the approved purpose. Restrict access to raw events, record provenance and changes, and keep a minimized audit trail with retention boundaries and accountable owners. |

To diagnose a stale answer, compare the authorized write event, active state, payload sent to the model, and the final answer. If the correction is absent from storage, inspect the write path. If the active value is correct but an older record is delivered, inspect selection or caching. If the correct record was delivered and the reply repeats the old value, inspect synthesis. When a cross-account read is confirmed, contain the affected path and use the incident workflow from [Decision defense, incident response and teaching](#m15-t02). Do not reproduce private values in the wider report.

Real reference judgments may need an independent reviewer. Give them the evidence actually delivered, the question, order scope, effective policy and the annotated claims. Have them record separate verdicts for retrieval, availability, support, decision and privacy. Ask them to identify the first supported failure and name any alternative explanation. If evidence is unavailable, preserve uncertainty. An automated judge supplied only with the final answer cannot confirm a successful retrieval, a correctly scoped read or whether the cited source was delivered.

## Knowledge Check

- What evidence separates a retrieval miss from a context omission?
- What must stay fixed to interpret a position comparison?
- Why should an expired correction avoid restoring a prior note?

## Knowledge Check Answers

- Compare required IDs against the recorded retrieval candidates and exact delivered passages. A candidate found by retrieval can still be cut before the prompt.
- Within each slice, keep the question, source set, instructions, budget and model configuration fixed. Move evidence and record the delivered position. Repeat before claiming a reliable model effect.
- A correction superseded the prior value. If it expires, ask the user or apply an authorized fallback unless a documented policy explicitly says otherwise.

## Common Mistakes

- **Treat every retrieved passage as delivered.** Save the final payload and budget decisions.
- **Count well-formed citations as proof.** Verify the specific claim, source and applicable version.
- **Select a preference by recency alone.** Check account, case, purpose and active status first.
- **Approve while a known critical read remains.** Keep the scope breach visible and require a verified correction.
