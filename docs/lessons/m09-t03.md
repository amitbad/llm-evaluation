## Beginner Explanation

### Save one check before building a suite

Take the question “What proof is required for a refund?” Northstar expects “A valid receipt is required.” Prompt-V1’s saved answer is “Receipt optional.” Prompt-V2’s saved answer is “A valid receipt is required.” Give this test the ID `Q01`. The question, reference answer, and rule for deciding pass or fail form one **test case**. A **dataset** is the reviewed collection of cases. A **suite** adds the configurations and checks needed to run those cases consistently.

An **assertion** is one check, such as whether the two strings are identical. The **evaluator** applies the check and records evidence. A **threshold** is a documented minimum for a graded score or a release condition. A **test run** captures which cases, prompt versions and checks were used. A **report** presents results so someone else can inspect them. A **regression** is a case that passed under the baseline, then fails under the candidate. A missing result cannot establish one.

If reviewers use different words for the same accepted answer, decide whether exact equality is justified. If the assistant must output a strict JSON shape for downstream code, check the structure. If you need to know whether a paraphrase follows policy, use a rubric with concrete acceptance criteria, compare a judge with human-reviewed cases, and keep disagreements visible. People are needed to settle ambiguous expectations and assess critical cases. A model judge also needs a configured model endpoint, unless you are reading a saved judgment.

### Describe the test before running it

A **prompt template** contains placeholders for values from a case. For example, `Question: {{question}}` inserts the saved question. A **provider** is the implementation that produces or returns the output. It could call a model endpoint, or in the walkthrough it could just return the fixture you supplied. Keep the provider, model revision, template, dataset, and expected outputs identifiable. If both the model and the prompt change in one trial, you cannot attribute a change to either one alone.

Start with Q01’s expected answer. In YAML, `expected: A valid receipt is required.` stores the text under the name `expected`. A dash starts each entry under `tests`, and indentation keeps that case’s `vars` and `assert` together. In the assertion, `value: '{{expected}}'` tells promptfoo to compare the output with the approved text for the current row. If you move the assertion to Q02, the same placeholder resolves to the warranty answer. Unlike the Python runner in M09-T01, where you wrote the loop, promptfoo reads the configuration and constructs the prompt-by-provider-by-case combinations. Two prompt variants, one provider and two cases give four combinations before any repetitions.

### Pick an assertion that can ask the right question

Predict what happens if “A valid receipt is **not** required” goes through a rule looking for “valid receipt.” The phrase is present and the policy is wrong. Exact equality catches this specific disagreement but may reject a good paraphrase. Normalize only differences the rubric explicitly allows, such as case or whitespace. Regular expressions can check token boundaries and forms. JSON parsing only checks that the text can be read. A schema adds required fields and type checks, and another policy assertion still needs to check the actual value.

The pinned promptfoo example uses `equals`. The assertion catalog also describes `contains`, `not-contains`, `regex`, and `is-json`. A model-graded `llm-rubric` check evaluates prose against a grading instruction and needs a judge configuration. Review rubric calibration on frozen examples before using its output as a gate. [Promptfoo assertion reference](https://www.promptfoo.dev/docs/configuration/expected-outputs/).

### Know which OpenAI workflow a saved run came from

The historical open-source `openai/evals` repository is a Python harness and benchmark registry. It has its own runners, task specs, and result files. OpenAI Platform Evals has a separate managed API for eval definitions, runs, and per-item results. Its request bodies are not local harness configs. **The managed Evals platform became read-only for existing users on October 31, 2026, and is scheduled to shut down November 30, 2026.** The walkthrough preserves its format for reading and migrating saved runs. Use promptfoo or the local fixture suite for new runs. [Historical open-source repository](https://github.com/openai/evals), [OpenAI deprecation schedule](https://developers.openai.com/api/docs/deprecations), and [OpenAI migration walkthrough](https://developers.openai.com/cookbook/examples/evaluation/moving-from-openai-evals-to-promptfoo).

In promptfoo you own the YAML, fixture files, provider configuration, and exported results. That makes a local deterministic check easy to repeat in continuous integration (CI), where a test runs on a code change. In the managed Evals model, the service owns the definition and run IDs. Each data item supplies fields the grader references. Historically a run could grade existing captures or generate samples using a configured model. Preserve IDs and exports for migrations. Both workflows can run exact comparisons and use model grading where configured. The costs and data paths differ. A local Echo check uses no model. A hosted grader or model provider can see the data you submit and may incur cost. Use approved endpoints and check provider retention, project access, and output visibility. Bring borderline cases to human review regardless of which tool created the report.

### Route errors separately from assertions

Translate outputs into the M09-T01 contract. Keep case ID, evaluator ID and version, status, score, verdict, reason, evidence, and error code. Add prompt and dataset versions. `OK` with `passed=False` and score zero means a valid check rejected the output. `ERROR` means a valid check could not be completed. A timeout, invalid tool result, bad provider configuration, or malformed test configuration belongs there or in preflight. A missing reference can make a check `SKIPPED`. A planned row with no capture is `MISSING` in this lesson’s local report. Neither supplies a score. A captured invalid JSON reply is a valid schema assertion failure because a reply exists to score.

A tool’s filter or summary can hide rows. Join by the case and prompt IDs, and count expected records before comparing results. When planning CI, fix the suite, data and config versions, run the documented command on a change, and publish an access-controlled artifact. Fail the policy gate for confirmed critical findings. Block automatic release for missing coverage, configuration errors, or regressions that still need review. Let a reviewer inspect the case and assertion evidence.

Treat all model replies and fixture text as untrusted data. Parse expected structures and grade text without executing commands found in it. Use synthetic questions, avoid sending sensitive records to unapproved providers, keep credentials in an environment variable or secret store, and give result access and retention an explicit owner. A credential in a configuration file or a pasted reply can end up in logs and artifacts. For prompt-injection evaluation use isolated fixtures and verify that the application continues to follow its authorized instructions. This lesson’s harness runs only the assertions written in the suite.

### Step 1 — Validate a test suite

Northstar is about to merge two refund test lists. Confirm that a case has one stable ID, one question, and one expected answer.

One dictionary holds one task and its expected reply. A set remembers IDs already seen. `in` checks whether a record repeats an ID, and `append` adds an error without losing the previous rows.

[Open Python Editor](https://www.online-python.com/)

```python
cases = [
    {"id": "Q1", "question": "What is the deadline?", "expected": "30 days."},
    {"id": "Q2", "question": "What proof do I need?", "expected": "A valid receipt."},
]
duplicate = False
if duplicate:
    cases.append(dict(cases[0]))
seen = set()
errors = []
for row in cases:
    if any(not row.get(field) for field in ("id", "question", "expected")):
        errors.append("missing required field")
    elif row["id"] in seen:
        errors.append("duplicate " + row["id"])
    else:
        seen.add(row["id"])
print("IDs:", ", ".join(sorted(seen)))
print("Validation:", ", ".join(errors) or "OK")
```

```text
IDs: Q1, Q2
Validation: OK
```

**Predict and modify.** Set `duplicate` to `True`. Predict whether two Q1 rows can enter the comparison.

```text
IDs: Q1, Q2
Validation: duplicate Q1
```

The duplicate can overwrite or double-count a result. Investigate the dataset before running the suite.

**Checkpoint.** Which row needs repair? Investigate the duplicate before either Q1 row contributes to a report.

### Step 2 — Compare two prompts on identical cases

The same deadline and receipt questions were asked of V1 and V2. Trace the two rows manually before comparing the labels.

Keep the question IDs and expected outputs fixed. Each dictionary maps an ID to a fictional captured reply. `items()` yields the key and value. A change from `True` to `False` on the same case is a regression.

[Open Python Editor](https://www.online-python.com/)

```python
expected = {"Q1": "30 days.", "Q2": "A valid receipt."}
v1 = {"Q1": "30 days.", "Q2": "Receipt optional."}
v2 = {"Q1": "30 days.", "Q2": "A valid receipt."}
regress = False
if regress:
    v2["Q1"] = "90 days."
for key, reference in expected.items():
    before = v1[key] == reference
    after = v2[key] == reference
    transition = "regression" if before and not after else "fix" if after and not before else "unchanged"
    print(key, before, "->", after, transition)
```

```text
Q1 True -> True unchanged
Q2 False -> True fix
```

**Predict and modify.** Set `regress` to `True`. Predict which test still improves and which now regresses.

```text
Q1 True -> False regression
Q2 False -> True fix
```

Q2 remains a fix. Q1 becomes a regression. A total alone would hide the difference.

**Checkpoint.** Which case would you inspect first? Q1 regressed under the changed capture, even though the Q2 improvement remains.

### Step 3 — Spot a weak assertion

Northstar wants to catch a reply that reverses the receipt rule. Compare what an exact, required-text and forbidden-text check can see.

An assertion is a rule about one output. `==` tests exact equality, `in` looks for text, and `not in` checks its absence. `casefold()` ignores capitalization for this small exercise.

[Open Python Editor](https://www.online-python.com/)

```python
answer = "A valid receipt is required."
negation = False
if negation:
    answer = "A valid receipt is not required."
text = answer.casefold()
print("Exact:", text == "a valid receipt is required.")
print("Required phrase:", "valid receipt" in text)
print("No wrong number:", "90" not in text)
```

```text
Exact: True
Required phrase: True
No wrong number: True
```

**Predict and modify.** Set `negation` to `True`. Which checks can the wrong answer still pass?

```text
Exact: False
Required phrase: True
No wrong number: True
```

The negated reply still contains the required phrase, and it never mentions the forbidden number. Those checks therefore pass even though the reply reverses the receipt rule. Exact equality rejects this fixture. If your rubric accepts paraphrases, add a reviewed negation example to test whether the broader grading rule catches the same failure.

**Checkpoint.** Does the word check test the rule’s meaning? Add the negated example to the suite and review the answer as a whole.

### Step 4 — Validate a structured answer

The refund application expects a JSON object with a numeric deadline. Predict whether removing the deadline makes the response invalid JSON or simply invalid for this application.

`json.loads` parses JSON text. A parseable object can still lack required fields or use the wrong types. `type(value) is int` avoids treating the Python Boolean `True` as the integer 1.

[Open Python Editor](https://www.online-python.com/)

```python
import json
omit_field = False
data = {"eligible": False, "days": 30}
if omit_field:
    del data["days"]
raw = json.dumps(data)
parsed = json.loads(raw)
schema = {"eligible": bool, "days": int}
problems = [key for key, expected in schema.items()
            if type(parsed.get(key)) is not expected]
print("JSON parsed:", isinstance(parsed, dict))
print("Schema:", "FAIL " + ", ".join(problems) if problems else "PASS")
```

```text
JSON parsed: True
Schema: PASS
```

**Predict and modify.** Set `omit_field` to `True`. Predict whether parsing or validation fails.

```text
JSON parsed: True
Schema: FAIL days
```

Parsing succeeds. Schema validation finds that the limit is missing. Check policy facts after checking shape.

**Checkpoint.** Which failure should the report name? The reply parses, but it fails the required-field check.

### Step 5 — Normalize results into a shared contract

Northstar receives a local assertion result and an illustrative managed-grader row. Convert them to the same reporting fields so a failure and a timeout remain distinct.

These two input shapes are teaching adapters, not real API responses. The shared record retains the stable case and evaluator IDs. `None` represents the absence of a valid measurement.

[Open Python Editor](https://www.online-python.com/)

```python
timed_out = False
raw = [
    ("promptfoo-fixture", {"success": False}),
    ("managed-fixture", {"outcome": "timeout" if timed_out else "pass"}),
]
for tool, item in raw:
    error = item.get("outcome") == "timeout"
    passed = None if error else item.get("success", item.get("outcome") == "pass")
    row = {"case_id": "Q1", "evaluator_id": "equality", "version": "1",
           "status": "ERROR" if error else "OK", "score": None if error else int(passed),
           "passed": passed, "reason": "provider timeout" if error else "scored",
           "evidence": item, "error": "TIMEOUT" if error else None}
    print(tool, row["status"], row["score"], row["passed"], row["error"])
```

```text
promptfoo-fixture OK 0 False None
managed-fixture OK 1 True None
```

**Predict and modify.** Set `timed_out` to `True`. Compare the first tool’s valid failure with the second tool’s error.

```text
promptfoo-fixture OK 0 False None
managed-fixture ERROR None None TIMEOUT
```

The valid failure still has score zero. The timeout has no valid score and must reduce coverage rather than enter the average.

**Checkpoint.** Should the timeout add a failure to the model’s pass rate? Leave its score and verdict unset and record the infrastructure error.

### Step 6 — Calculate pass rate and coverage

An engineer can report that three results were scored yet still owe the team a fourth result. Measure answer pass rate, coverage and category regressions separately.

A result can be planned even when no capture arrived. `get` returns `None` for absent keys. The comprehension collects only `OK` results for the pass-rate denominator.

[Open Python Editor](https://www.online-python.com/)

```python
cases = {"Q1": "refund", "Q2": "shipping", "Q3": "warranty", "Q4": "account"}
previous = {"Q1": True, "Q2": True, "Q3": True, "Q4": True}
candidate = {"Q1": ("OK", True), "Q2": ("OK", False), "Q3": ("ERROR", None),
             "Q4": ("OK", True)}
remove_capture = False
if remove_capture:
    del candidate["Q4"]
valid = {key: passed for key, (status, passed) in candidate.items() if status == "OK"}
regressions = [cases[key] for key, passed in valid.items() if previous[key] and not passed]
print(f"Pass rate: {sum(valid.values())}/{len(valid)}")
print(f"Coverage: {len(valid)}/{len(cases)}")
print("Errors:", sum(status == "ERROR" for status, _ in candidate.values()))
print("Missing:", len(cases.keys() - candidate.keys()))
print("Critical failures:", int(valid.get("Q1") is False))
print("Regression categories:", ", ".join(regressions) or "none")
```

```text
Pass rate: 2/3
Coverage: 3/4
Errors: 1
Missing: 0
Critical failures: 0
Regression categories: shipping
```

**Predict and modify.** Set `remove_capture` to `True`. Which fraction uses the original four planned cases?

```text
Pass rate: 1/2
Coverage: 2/4
Errors: 1
Missing: 1
Critical failures: 0
Regression categories: shipping
```

Coverage keeps the four-case denominator. The valid denominator falls and the shipping regression stays visible.

**Checkpoint.** Does a higher-looking proportion justify release? Check which successful result disappeared and use the planned case count for coverage.

### Step 7 — Apply a release policy after scoring

V2 can gain more passing cases and still make a serious refund mistake. Apply a release policy to the captured outcomes.

Cases Q1 and Q2 used to fail. Q3 passed, and Q4 is the critical refund decision. A gate is a condition that must pass before release. `all` checks whether every value is true after the critical check.

[Open Python Editor](https://www.online-python.com/)

```python
baseline = {"Q1": False, "Q2": False, "Q3": True, "Q4": True}
critical_regression = False
candidate = {"Q1": True, "Q2": True, "Q3": True, "Q4": not critical_regression}
if not candidate["Q4"]:
    decision = "HOLD"
elif not all(candidate.values()):
    decision = "REVIEW"
else:
    decision = "RELEASE"
print(f"Passes: {sum(baseline.values())}/4 -> {sum(candidate.values())}/4")
print("Critical failures:", int(not candidate["Q4"]))
print("Decision:", decision)
```

```text
Passes: 2/4 -> 4/4
Critical failures: 0
Decision: RELEASE
```

**Predict and modify.** Set `critical_regression` to `True`. Compare overall pass count and release status.

```text
Passes: 2/4 -> 3/4
Critical failures: 1
Decision: HOLD
```

The candidate still gains one pass overall. A new critical policy error overrides that gain.

**Checkpoint.** What is the next engineering action? Inspect the critical case and rerun the complete suite after repair.

import json
import re

mode = "baseline"  # baseline, repair, missing, retry, or negation
dataset = "northstar-prompts-v1"
config = "northstar-assertions-v1"
prompts = {
    "Prompt-V1": "Answer using the supplied policy. Follow the requested output format.",
    "Prompt-V2": "Answer concisely using only the supplied policy. Follow the requested output format.",

policy = "Refunds require a valid receipt and a request within 30 days of purchase."

    ("Q4", "warranty", "Where do I start a claim?", "Start from your order page.", ("order-phrase", "equals")),

    ("Q6", "escalation", "Where do I escalate this?", "Use the case page.", ("equals",)),
    ("Q7", "citation", "Return the authorized refund source ID as JSON.", None, ("citation-schema", "citation-id")),
    ("Q8", "critical refund", "Purchased 45 days ago with a receipt. Is it eligible? JSON with days and eligible.",
     None, ("eligibility-schema", "deadline", "ineligible")),
)
v1 = {
    "Q1": '{"days":30}', "Q2": "Receipt optional.", "Q3": "Ask any time.",
    "Q4": "Start from your order page.", "Q5": "Use sign-in.", "Q6": "Send email.",
    "Q7": '{"citation":"RF"}', "Q8": '{"days":30,"eligible":false}',
}
# A timeout is a capture error. No key for Q7 means no capture was saved.
v2 = {
    **v1, "Q2": "A valid receipt.", "Q3": "Contact support after 45 days.",
    "Q6": {"error": "TIMEOUT"}, "Q8": '{"days":90,"eligible":true}',
}
del v2["Q7"]

rule_ids = {
    "days-schema", "deadline", "equals", "shipping-regex", "no-anytime", "order-phrase",
    "citation-schema", "citation-id", "eligibility-schema", "ineligible",
}
schemas = {
    "days-schema": {"days": int},
    "citation-schema": {"citation": str},
    "eligibility-schema": {"days": int, "eligible": bool},
}

def validate(records, *captures):
    ids = [case[0] for case in records]
    if len(ids) != len(set(ids)):
        raise ValueError("duplicate case IDs")
    for key, category, question, expected, checks in records:
        if any(not isinstance(value, str) or not value.strip() for value in (key, category, question)):
            raise ValueError("missing required case information")
        if not checks or len(set(checks)) != len(checks) or set(checks) - rule_ids:
            raise ValueError("unknown or duplicate assertions")
        if expected is not None and not isinstance(expected, str):
            raise ValueError("invalid reference")
    if any(set(capture) - set(ids) for capture in captures):
        raise ValueError("unknown capture ID")

def decisions(checks, expected, raw, parsed):
    return {
        "equals": None if expected is None else raw == expected,
        "shipping-regex": bool(re.search(r"\b45 days\b", raw)),
        "no-anytime": "any time" not in raw.casefold(),
        "order-phrase": "order page" in raw.casefold(),
        "deadline": type(parsed.get("days")) is int and parsed["days"] == 30,
        "citation-id": parsed.get("citation") == "RF" and "RF" in source_text,
        "ineligible": parsed.get("eligible") is False,
        **{rule: all(type(parsed.get(key)) is kind for key, kind in schema.items())
           for rule, schema in schemas.items() if rule in checks},
    }

def assess(case, captured, version):
    key, category, _question, expected, checks = case
    row = {"case_id": key, "prompt_version": version, "category": category,
           "evaluator_id": "northstar-policy-suite", "version": config, "score": None,
           "passed": None, "reason": "", "evidence": {}, "error": None, "critical": False}
    if key not in captured:
        return {**row, "status": "MISSING", "reason": "no capture saved"}
    raw = captured[key]
    if not isinstance(raw, str):
        error = raw.get("error") if isinstance(raw, dict) else None
        error = error if error in ("TIMEOUT", "RATE_LIMIT") else "INVALID_CAPTURE"
        return {**row, "status": "ERROR", "error": error, "reason": "capture could not be graded"}
    parsed = {}
    if set(checks) & schemas.keys():
        try:
            value = json.loads(raw)
        except ValueError:
            value = None
        if isinstance(value, dict):
            parsed = value
    results = decisions(checks, expected, raw, parsed)
    evidence = {name: results[name] for name in checks}
    critical = key == "Q8" and (parsed.get("eligible") is True or
                                 (type(parsed.get("days")) is int and parsed["days"] != 30))
    if None in evidence.values():
        return {**row, "status": "SKIPPED", "reason": "missing reference",
                "evidence": evidence, "critical": critical}
    passed = all(evidence.values())
    return {**row, "status": "OK", "passed": passed, "score": int(passed),
            "reason": "all assertions passed" if passed else "assertion mismatch",
            "evidence": evidence, "critical": critical}

def ratio(n, d):
    return f"{n}/{d}" if d else "N/A"

def summarize(rows):
    valid = [row for row in rows if row["status"] == "OK"]
    counts = {kind: sum(row["status"] == kind for row in rows)
              for kind in ("ERROR", "MISSING", "SKIPPED")}
    return (f"pass={ratio(sum(row['passed'] for row in valid), len(valid))} "
            f"coverage={len(valid)}/{len(rows)} errors={counts['ERROR']} "
            f"missing={counts['MISSING']} skips={counts['SKIPPED']} "
            f"critical={sum(row['critical'] for row in rows)}")

def tag(row):
    return ("PASS" if row["passed"] else "FAIL") if row["status"] == "OK" else row["status"]

def compare(name, records, baseline, candidate, candidate_version):
    validate(records, baseline, candidate)
    old = [assess(case, baseline, "Prompt-V1") for case in records]
    new = [assess(case, candidate, candidate_version) for case in records]
    paired = [(a, b) for a, b in zip(old, new, strict=True) if a["status"] == b["status"] == "OK"]
    fixes = [b["case_id"] for a, b in paired if not a["passed"] and b["passed"]]
    regressions = [f"{b['case_id']} ({b['category']})" for a, b in paired if a["passed"] and not b["passed"]]
    if any(row["critical"] for row in new):
        result = "HOLD"
    elif len(records) != 8 or len(paired) != len(records) or regressions or not all(row["passed"] for row in new):
        result = "REVIEW"
    else:
        result = "RELEASE"
    print(f"{name} | {dataset} | {config} | Prompt-V1 vs {candidate_version}")
    print("Case | V1 | candidate | candidate evidence")
    for a, b in zip(old, new, strict=True):
        details = ", ".join(f"{rule}={value}" for rule, value in b["evidence"].items())
        print(f"{b['case_id']} | {tag(a)} | {tag(b)} | {details or b['error'] or b['reason']}")
    print("V1:", summarize(old))
    print("Candidate:", summarize(new))
    print(f"Matched passes: {ratio(sum(a['passed'] for a, _ in paired), len(paired))} -> "
          f"{ratio(sum(b['passed'] for _, b in paired), len(paired))}")
    print(f"Fixes: {', '.join(fixes) or 'none'} | Regressions: {', '.join(regressions) or 'none'}")
    print("Decision:", result)
    return json.dumps({"run": name, "dataset": dataset, "config": config,
                       "prompts": prompts, "policy": policy, "sources": source_text,
                       "cases": records, "baseline": baseline, "candidate": candidate,
                       "baseline_results": old, "candidate_results": new, "decision": result},
                      sort_keys=True, allow_nan=False)

def replay(choice):
    history = (compare("baseline", cases, v1, v2, "Prompt-V2"),)
    if choice == "baseline":
        print("Audit runs:", len(history))
        return history
    repaired = {**v2, "Q8": '{"days":30,"eligible":false}'}
    version = "Prompt-V2/capture-repair"
    history += (compare("repair", cases, v1, repaired, version),)
    if choice == "missing":
        incomplete = {key: value for key, value in repaired.items() if key != "Q3"}
        history += (compare("missing", cases, v1, incomplete, version),)
    elif choice == "retry":
        retry = {**repaired, "Q6": "Use the case page."}
        history += (compare("retry", cases, v1, retry, version),)
    elif choice == "negation":
        negated = {**repaired, "Q4": "Do not start from your order page."}
        history += (compare("negation", cases, v1, negated, version),)
    elif choice != "repair":
        raise ValueError("unknown run mode")
    print("Audit runs:", len(history), "| original Q8:", json.loads(history[0])["candidate"]["Q8"])
    return history
