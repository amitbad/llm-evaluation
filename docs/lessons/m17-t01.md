## Beginner Explanation

### Fill in a value and choose a label

Read “Order NS-1042 has not arrived. I want a refund.” **Information extraction** copies or derives a supported value from the message. Here the order identifier is NS-1042. A **field** is the named place to store that value. **Classification** chooses a label from a fixed set. Here the requested outcome is `refund_request` even though the issue itself concerns delivery.

**JSON** is a text format for exchanging data. An object groups names and values between braces. The expected object is `{"order_id": "NS-1042", "intent": "refund_request"}`. Parsing turns the JSON text into data, such as a Python dictionary. A **schema** specifies what that object may contain. A required field has to be present. An optional field may be absent. A nullable field can contain `null`, represented by `None` in Python. A field can be both required and nullable.

A valid record can still be wrong. `NS-1043` has the same format as `NS-1042`. Only the second matches the requested order. A valid intent label can also be wrong for the message. Check syntax, schema and evidence separately before evaluating any action.

### Define what each label means

| Routing label | Include | Exclude or seek clarification |
| --- | --- | --- |
| refund_request | Explicit money-back request | Mere mention of a missing parcel with no request for a refund |
| replacement_request | Explicit exchange or replacement | A device fault with no request for a replacement |
| delivery_issue | Tracking, delay or missing-delivery request without a replacement or refund request | A delivery issue with a clear requested refund, which has refund intent and delivery as its issue category |
| technical_support | Request for troubleshooting or setup help | A defect mentioned only to explain a replacement request |
| other | A supported general question outside this taxonomy | Unresolved conflicting actions, which have no confirmed intent label |

This is a **single-label** intent taxonomy. A separate issue category or escalation flag may coexist with the intent. In **multi-label** classification, several intent labels can apply, so you would define which combinations are permitted and score all predicted and expected labels. Here a genuine dispute between refund and replacement requires clarification rather than an arbitrary tie break.

## Worked Demonstration

### Ask what each denominator counts

Use a worked form with five filled fields. The candidate matches four fields and mistypes the order ID. **Field accuracy** is 4/5. **Whole-record exact match** is zero for that form because all five must match. If the form has two entities and identical values appear in both, include the entity ID in the scoring unit. Otherwise a correct amount assigned to the wrong order could receive credit.

Now score non-null extractions as triples of case ID, field and value. Suppose three values match, one expected value is missed, and one unsupported value is added. Three predictions are **true positives**. The unsupported value is a **false positive** and the omitted one is a **false negative**. Precision asks how many predictions were right, here 3/4. Recall asks how many expected values were recovered, also 3/4. **F1** balances the two. Using counts, it is twice the matches divided by twice the matches plus false positives and false negatives, here 6/8. A wrong non-null value for a filled field contributes one false positive and one false negative. A correctly empty field earns accuracy credit but is no extracted-value match. Report undefined denominators or an explicit zero convention.

**Classification accuracy** counts cases whose intent label matches. A **confusion matrix** uses a row for each true label and a column for each predicted label. Its diagonal contains correct cases. For a given class, the off-diagonal values in its column are false positives and those in its row are false negatives. **Micro F1** pools the class totals. In a complete single-label multiclass set it equals accuracy, since each wrong prediction adds one false positive and one false negative. **Macro F1** averages the class F1 scores equally. It can expose weaker rare classes when most messages use one frequent label. Neither average replaces a gate on critical fields or classes. [Classification metric definitions](https://scikit-learn.org/stable/modules/model_evaluation.html#classification-metrics)

### Experiment B — Validate a nested record and its meaning separately

Add a required nested routing object with a `priority` enum. An enum is a closed list of allowed values. Add an optional `note` that, when supplied, must be a string. Keep the order key required but nullable. The schema accepts an explicit unknown even though the current message supports a known order. A correct grader still fails that answer.

Sets compare the allowed keys. `isinstance` distinguishes objects and strings. `re.fullmatch` applies the identifier pattern to the whole string. This small validator demonstrates the rules on fixed inputs. The release lab also rejects duplicate keys before validating the record. [Python JSON decoder](https://docs.python.org/3/library/json.html)

[Open Python Editor](https://www.online-python.com/)

```python
import json
import re

REFERENCE = {"order_id": "NS-1042", "intent": "refund_request", "routing": {"priority": "routine"}}
REQUIRED = {"order_id", "intent", "routing"}


def schema(record):
    if not isinstance(record, dict) or REQUIRED - record.keys():
        return "missing keys or wrong object type"
    if record.keys() - (REQUIRED | {"note"}):
        return "unexpected field"
    if "note" in record and not isinstance(record["note"], str):
        return "note type"
    code = record["order_id"]
    if code is not None and (not isinstance(code, str) or not re.fullmatch(r"NS-[0-9]{4}", code)):
        return "invalid ID"
    routing = record["routing"]
    if (record["intent"] not in ("refund_request", "replacement_request", "delivery_issue")
            or not isinstance(routing, dict) or set(routing) != {"priority"}
            or routing["priority"] not in ("routine", "escalate")):
        return "intent or routing shape/value"
    return "valid"


rows = [
    ("complete", json.dumps(dict(REFERENCE, note="fixture"))),
    ("unknown", json.dumps(dict(REFERENCE, order_id=None))),
    ("missing", json.dumps({k: v for k, v in REFERENCE.items() if k != "order_id"})),
    ("wrong value", json.dumps(dict(REFERENCE, order_id="NS-1043"))),
    ("bad type", json.dumps(dict(REFERENCE, order_id=1042))),
    ("bad enum", json.dumps(dict(REFERENCE, routing={"priority": "fastest"}))),
    ("extra key", json.dumps(dict(REFERENCE, approved=True))),
    ("syntax", "{"),
]
for name, raw in rows:
    try:
        parsed = json.loads(raw)
    except json.JSONDecodeError:
        print(f"B {name}: parse failed")
        continue
    result = schema(parsed)
    facts = result == "valid" and all(parsed[k] == v for k, v in REFERENCE.items())
    print(f"B {name}: {result}, facts={facts}")
```

```text
B unknown: valid, facts=False
B missing: missing keys or wrong object type, facts=False
B wrong value: valid, facts=False
B bad type: invalid ID, facts=False
B bad enum: intent or routing shape/value, facts=False
```

The optional note is outside this example's factual reference and does not reduce its score. The unknown record passes the shape check and fails the verified ID check. Change `routing` from a dictionary to a string. The record still parses but fails the nested schema. ### Experiment C — Score fields, records and the order span

Expand the headset case to order ID, product, purchase date, issue and requested action. The reference uses the exact ID and ISO date `2026-03-12`. The candidate changes the ID by one digit. The expected ID is in the source at a Python character span `[start, end)`, where the end is excluded. Span alignment checks that those positions cover the exact string. It cannot by itself show that the span refers to the right order if the message names several.

`enumerate` and slicing can help locate the reference. Here `index` locates the substring and `len` computes the end. A dictionary comprehension names every field match. `and`, `sum` and `all` give evidence counts and the whole-record verdict.

[Open Python Editor](https://www.online-python.com/)

```python
message = ("I ordered a headset on 12 March 2026. Order NS-1042. "
           "The left speaker is not working. I want a replacement.")
reference = {"order_id": "NS-1042", "product": "headset", "purchase_date": "2026-03-12",
             "issue": "left speaker is not working", "requested_action": "replacement"}

start = message.index(reference["order_id"])
end = start + len(reference["order_id"])

tp = sum(matches[key] and value is not None for key, value in candidate.items())
fp = sum(not matches[key] and value is not None for key, value in candidate.items())
fn = sum(not matches[key] and value is not None for key, value in reference.items())
print(f"C field accuracy={sum(matches.values())}/{len(matches)}, record_exact={all(matches.values())}")
print(f"C order span={start}:{end}, source={message[start:end]}, aligned={message[start:end] == candidate['order_id']}")
print(f"C TP={tp}, FP={fp}, FN={fn}, precision={tp/(tp+fp):.2f}, recall={tp/(tp+fn):.2f}, "
```

### Experiment D — Compare a majority baseline with a revised classifier

The frozen list contains eight delivery cases and one case from each of the other four classes. The baseline guesses delivery for every row. It gets 8/12 correct and has zero replacement recall. The revision improves three minority labels, mislabels one delivery case and still misses the replacement. Fix only that replacement prediction and inspect the rare-class effect.

Build a zero-filled nested dictionary for true rows and predicted columns. `zip(..., strict=True)` pairs each reference with its prediction and catches unequal list lengths. For a class, subtract its diagonal count from its row sum or column sum to find misses or false alarms. This toy uses 0 when a precision denominator is zero and keeps the class's support count visible.

[Open Python Editor](https://www.online-python.com/)

```python
labels = ("refund_request", "replacement_request", "delivery_issue", "technical_support", "other")
fixtures = [
    ("Where is the parcel?", "delivery_issue"),
    ("The parcel is late.", "delivery_issue"),
    ("Tracking stopped.", "delivery_issue"),
    ("Delivery status please.", "delivery_issue"),
    ("When does delivery arrive?", "delivery_issue"),
    ("Order shows no tracking.", "delivery_issue"),
    ("The parcel did not arrive.", "delivery_issue"),
    ("Is the parcel still in transit?", "delivery_issue"),
    ("I want my money back.", "refund_request"),
    ("Send a replacement please.", "replacement_request"),
    ("Help me pair the headset.", "technical_support"),
    ("What are your opening hours?", "other"),
]
actual = [label for _, label in fixtures]
baseline = ["delivery_issue"] * len(fixtures)
revision = ["delivery_issue"] * 7 + ["other", "refund_request", "delivery_issue", "technical_support", "other"]


def ratio(num, den):
    return num / den if den else 0.0


for name, predicted in (("majority", baseline), ("revised", revision)):
    matrix = {true: dict.fromkeys(labels, 0) for true in labels}
    for true, prediction in zip(actual, predicted, strict=True):
        matrix[true][prediction] += 1
    f1s = []
    matches = 0
    print(f"D {name} columns={','.join(labels)}")
    for label in labels:
        tp = matrix[label][label]
        support = sum(matrix[label].values())
        predicted_count = sum(matrix[key][label] for key in labels)
        fp, fn = predicted_count - tp, support - tp
        p, r = ratio(tp, tp + fp), ratio(tp, tp + fn)
        f1 = ratio(2 * tp, 2 * tp + fp + fn)
        f1s.append(f1)
        matches += tp
        print(f"  {label}: {list(matrix[label].values())}, n={support}, P={p:.3f} R={r:.3f} F1={f1:.3f}")
    errors = len(actual) - matches
    print(f"  accuracy={ratio(matches, len(actual)):.3f}, macro={ratio(sum(f1s), len(f1s)):.3f}, "
          f"micro={ratio(2*matches, 2*matches+errors+errors):.3f}")
```

### Experiment E — Keep uncertainty in the record

### Experiment F — Normalize presentation with a documented rule

**Normalization** changes representation under a stated rule. Keep raw evidence, compare strict values and report normalized matches separately. Parse the same slash date only when the locale contract is known. Convert an explicitly USD-formatted amount to integer cents using `Decimal`, without currency conversion. Normalize product whitespace and case and allow an approved alias. Order identifiers, including leading zeros, are exact. These rules are for the fixture, so another product or locale needs its own versioned policy.

[Open Python Editor](https://www.online-python.com/)

```python
from datetime import datetime
from decimal import Decimal
import re

ALIASES = {"hs-01": "headset"}
UNRESOLVED = object()


def normalize(kind, value, locale):
    if kind == "date":
        pattern = {"en-GB": "%d/%m/%Y", "en-IN": "%d/%m/%Y", "en-US": "%m/%d/%Y"}.get(locale)
        if pattern is None:
            return UNRESOLVED
        try:
            return datetime.strptime(value, pattern).date().isoformat()
        except ValueError:
            return UNRESOLVED
    if kind == "money":
        if not re.fullmatch(r"USD [0-9]+\.[0-9]{2}", value):
            return UNRESOLVED
        return int(Decimal(value[4:]) * 100)
    if kind == "product":
        cleaned = " ".join(value.casefold().split())
        return ALIASES.get(cleaned, cleaned)
    return value


for name, kind, raw, expected, locale in (
    ("known date", "date", "03/04/2026", "2026-04-03", "en-GB"),
    ("different locale", "date", "03/04/2026", "2026-04-03", "en-US"),
    ("ambiguous date", "date", "03/04/2026", None, None),
    ("amount formatting", "money", "USD 25.00", 2500, None),
    ("wrong currency", "money", "EUR 25.00", 2500, None),
    ("case and spaces", "product", "  HEADSET  ", "headset", None),
    ("catalog alias", "product", "HS-01", "headset", None),
    ("leading zero lost", "order_id", "NS-007", "NS-0007", None),
):
    value = normalize(kind, raw, locale)
    result = "REVIEW" if value is UNRESOLVED else "PASS" if value == expected else "FAIL"
    print(f"F {name}: raw_match={raw == expected}, normalized={result}")
```

```text
F wrong currency: raw_match=False, normalized=REVIEW
```

The same date string resolves differently under two locale contracts. With no locale, the program sends it to REVIEW. Restoring only the missing zero in the identifier makes raw and normalized comparison pass. That is a candidate repair. A comparison rule must not pad IDs to hide the defect.

```python
from datetime import date
import json
import re

EXPORT_JSON = False
MARKER = "[SYNTHETIC-FOREIGN-FIELD]"
ID = re.compile(r"NS-[0-9]{4}")
LABELS = ("refund_request", "replacement_request", "delivery_issue", "technical_support", "other")
FIELDS = ("order_id", "product", "purchase_date", "issue", "requested_action", "intent",
          "issue_category", "priority", "amount_minor", "currency")
NULLABLE = {"order_id", "product", "purchase_date", "requested_action", "intent", "amount_minor", "currency"}
REASONS = ("unknown", "not_applicable", "ambiguous", "conflicting", "unsupported")
ROUTE_FIELDS = ("order_id", "amount_minor", "currency", "intent", "requested_action", "priority")
GATE = {"record_floor": 90, "robust_floor": 80, "robust_cases": 5}


def strict_load(raw):
    def unique(pairs):
        record = {}
        for key, value in pairs:
            if key in record:
                raise ValueError("duplicate key")
            record[key] = value
        return record

    def reject_constant(_):
        raise ValueError("non-finite constant")

    if len(raw.encode("utf-8")) > 8192:
        raise ValueError("size limit")
    return json.loads(raw, object_pairs_hook=unique, parse_constant=reject_constant)


def span(message, order):
    if order is None:
        return None
    start = message.find(order)
    return [start, start + len(order)] if start >= 0 else None


def make_record(message, issue, category, *, order=None, product=None, purchase=None, action=None,
                intent=None, priority="routine", amount=None, currency=None, uncertainty=None):
    out = dict(zip(FIELDS, (order, product, purchase, issue, action, intent, category, priority, amount, currency)))
    states = uncertainty or {}
    out["states"] = {key: states.get(key, "not_applicable") for key in FIELDS if out[key] is None}
    out["order_span"] = span(message, order)
    return out


def case(key, message, route, issue, category, **values):
    reference = make_record(message, issue, category, **values)
    trusted = {field: reference[field] for field in ROUTE_FIELDS}
    trusted["authorized"] = True
    trusted["clarification_required"] = route == "CLARIFY"
    return {"id": key, "message": message, "reference": reference, "trusted": trusted,
            "expected_route": route, "robust": key.startswith("G"), "reviewed": True}


CASES = [
    case("R01", "Refund USD 25.00 for order NS-1042. Parcel missing.", "WOULD_QUEUE_REFUND",
         "parcel missing", "delivery", order="NS-1042", action="refund", intent="refund_request",

def schema_error(record):
    if not isinstance(record, dict) or set(record) != set(FIELDS) | {"states", "order_span"}:
        return "shape or field names"
    states = record["states"]
    nulls = {key for key in FIELDS if record[key] is None}
    if (not isinstance(states, dict) or nulls - NULLABLE or set(states) != nulls
            or any(reason not in REASONS for reason in states.values())):
        return "null reasons"
    order, offsets = record["order_id"], record["order_span"]
    if order is not None:
        if (not isinstance(order, str) or not ID.fullmatch(order) or not isinstance(offsets, list)
                or len(offsets) != 2 or any(type(i) is not int or i < 0 for i in offsets)
                or not offsets[0] < offsets[1]):
            return "order ID or span"
    elif offsets is not None:
        return "span without ID"
    for field in ("product", "issue"):
        if record[field] is not None and (not isinstance(record[field], str) or not record[field].strip()):
            return field + " type"
    purchase = record["purchase_date"]
    if purchase is not None:
        try:
            if date.fromisoformat(purchase).isoformat() != purchase:
                return "date format"
        except (TypeError, ValueError):
            return "invalid date"
    if (record["intent"] not in (*LABELS, None)
            or record["requested_action"] not in ("refund", "replacement", "track", "troubleshoot", None)
            or record["issue_category"] not in ("billing", "delivery", "defect", "other")
            or record["priority"] not in ("routine", "escalate")):
        return "enum"
    amount, currency = record["amount_minor"], record["currency"]
    if (currency not in ("USD", None) or (amount is None) != (currency is None)
            or (amount is not None and (type(amount) is not int or not 0 <= amount <= 100000))):
        return "amount or currency"
    return None


def simulate(record, trusted):
    if not trusted["authorized"]:
        return "DENY_PERMISSION"
    for field, denial in (("order_id", "DENY_ID"), ("amount_minor", "DENY_AMOUNT"),
                          ("currency", "DENY_AMOUNT"), ("priority", "DENY_PRIORITY"),
                          ("intent", "DENY_INTENT"), ("requested_action", "DENY_INTENT")):
        if record[field] != trusted[field]:
            return denial
    if record["priority"] == "escalate":
        return "ESCALATE"
    concerns = set(record["states"].values()) - {"not_applicable"}
    action = record["requested_action"]
    if trusted["clarification_required"] or concerns:
        return "CLARIFY"
    if action == "refund":
        return "WOULD_QUEUE_REFUND" if record["amount_minor"] is not None else "CLARIFY"
    if action == "replacement":
        return "WOULD_QUEUE_REPLACEMENT" if record["product"] is not None else "CLARIFY"
    return "ROUTE_SUPPORT"


def normalized(key, value):
    if key == "product" and value is not None:
        cleaned = " ".join(value.casefold().split())
        return {"hs-01": "headset"}.get(cleaned, cleaned)
    return value


def grade(row, raw):
    result = {"id": row["id"], "parse": False, "schema": False, "evidenced": False,
              "exact": False, "raw": {}, "matched": {}, "unsupported": [],
              "critical": [], "route": "UNSCORED", "prediction": None, "error": None}
    if raw is None:
        result["error"] = "capture missing"
        return result
    if MARKER in raw:
        result["critical"].append("protected field")
    result["evidenced"] = row["reviewed"]
    try:
        record = strict_load(raw)
    except (ValueError, RecursionError):
        result.update(error="parse failure", route="REJECT_FORMAT")
        return result
    result["parse"] = True
    result["error"] = schema_error(record)
    if result["error"]:
        result["route"] = "REJECT_FORMAT"
        return result
    result["schema"] = True
    observed = record["order_span"]
    aligned = True
    if observed is not None:
        start, end = observed
        aligned = end <= len(row["message"]) and row["message"][start:end] == record["order_id"]
    route = "DENY_SPAN" if not aligned else simulate(record, row["trusted"])
    result["route"] = route
    if route.startswith("DENY_"):
        result["critical"].append(route)
    if route.startswith("WOULD_QUEUE_") and route != row["expected_route"]:
        result["critical"].append("unexpected queue route")
    if not row["reviewed"]:
        result["error"] = "review missing"
        return result
    expected = row["reference"]
    result["prediction"] = record["intent"]
    result["raw"] = {key: record[key] == expected[key] for key in FIELDS}
    result["matched"] = {key: normalized(key, record[key]) == normalized(key, expected[key]) for key in FIELDS}
    result["unsupported"] = [key for key in FIELDS if expected[key] is None and record[key] is not None]
    result["exact"] = (all(result["matched"].values()) and record["states"] == expected["states"]
                       and route == row["expected_route"] and not result["critical"])
    return result


def score(plan, captures):
    ids = [row["id"] for row in plan]
    if len(ids) != len(set(ids)) or set(captures) - set(ids):
        raise ValueError("duplicate case ID or unexpected capture")
    details = [grade(row, captures.get(row["id"])) for row in plan]
    n = len(details)
    parsed = sum(row["parse"] for row in details)
    schemas = sum(row["schema"] for row in details)
    coverage = sum(row["evidenced"] for row in details)
    passed = sum(row["exact"] for row in details)
    critical = [row["id"] for row in details if row["critical"]]
    field_counts = {key: {"raw_matches": sum(row["raw"].get(key, False) for row in details),
                          "matches": sum(row["matched"].get(key, False) for row in details),
                          "scored": sum(key in row["matched"] for row in details)} for key in FIELDS}
    matrix = {label: dict.fromkeys(LABELS, 0) for label in LABELS}
    class_planned = 0
    robust = [result for row, result in zip(plan, details, strict=True) if row["robust"]]
    for row, result in zip(plan, details, strict=True):
        true, prediction = row["reference"]["intent"], result["prediction"]
        if true is not None:
            class_planned += 1
            if prediction is not None:
                matrix[true][prediction] += 1
    class_scored = sum(sum(row.values()) for row in matrix.values())
    class_exact = sum(matrix[label][label] for label in LABELS)
    per_class = {}
    for label in LABELS:
        tp = matrix[label][label]
        fp = sum(matrix[truth][label] for truth in LABELS) - tp
        fn = sum(matrix[label].values()) - tp
        per_class[label] = {
            "tp": tp, "fp": fp, "fn": fn,
            "precision": tp / (tp + fp) if tp + fp else 0,
            "recall": tp / (tp + fn) if tp + fn else 0,
            "f1": 2 * tp / (2 * tp + fp + fn) if tp + fp + fn else 0,
        }
    robust_passed = sum(row["exact"] for row in robust)
    if critical:
        decision = "BLOCK"
    elif coverage < n or len(robust) < GATE["robust_cases"]:
        decision = "REVIEW"
    elif (schemas != n or 100 * passed < GATE["record_floor"] * n
          or 100 * robust_passed < GATE["robust_floor"] * len(robust)):
        decision = "BLOCK"
    else:
        decision = "PASS"
    return {"planned": n, "parsed": parsed, "schemas": schemas, "coverage": coverage, "passed": passed,
            "critical": critical, "decision": decision, "cases": details, "fields": field_counts,
            "classification": {"correct": class_exact, "scored": class_scored, "planned": class_planned,
                               "matrix": matrix, "per_class": per_class,
                               "micro_f1": class_exact / class_scored if class_scored else None,
                               "macro_f1": sum(item["f1"] for item in per_class.values()) / len(LABELS)
                               if class_scored else None},
            "robust": {"passed": robust_passed, "planned": len(robust)},
            "unsupported": sum(len(row["unsupported"]) for row in details)}
```

## Annotation and Design Review

Create the reference with the original case and frozen label instructions before looking at the candidate. Give two reviewers the same message separately. Ask them to label the field, affected entity, supporting character span and reason for any null. Have a third reviewer resolve disagreements using the approved policy and retain both original judgments. Change the reference version when correcting labels. The fixture reviews in this lesson are synthetic. They model how evidence is recorded.

| Extraction review criterion | What reviewers record | When to defer |
| --- | --- | --- |
| Entity and evidence | The intended order, plus a start-inclusive, end-exclusive span. Verify that the source slice returns the expected ID and that it belongs to the request. | Two orders are mentioned and neither is identified as the target. |
| Value and representation | The raw value and any permitted normalization. Record the locale, currency or product catalog entry that justifies a conversion. | A valid date can represent either 3 April or 4 March. |
| Intent and policy | One label from the definitions above, a separate issue category, and the policy basis for escalation if required. | Refund and replacement are both requested as mutually exclusive actions. |
| Absence and uncertainty | The field and its reason, such as unknown, not applicable, ambiguous, conflicting or unsupported. | Reviewers cannot agree that a nullable field is outside the task. |
| Label quality | Reviewer IDs, evidence, adjudication and taxonomy version. | No qualified reviewer can verify an unfamiliar language or policy. |

An application may attach a **confidence score** to a field. Validate its range separately from its meaning. A score of 0.95 does not establish 95% correctness. On a separate held-out dataset, group similar confidence scores and measure the proportion correct in each group, including rare labels. Compare how many cases remain scored when you defer the low-confidence ones. For example, if 8 of 10 retained order predictions are correct and 2 of the original 12 were deferred, report 8/10 accuracy and 10/12 coverage. A score never grants authorization.

For production evaluation, group near-duplicate messages and variations of the same order before splitting development and held-out data. Keep references and trusted snapshots out of model input. Keep the minority slices, unexpected-field controls and missing-evidence cases in the release suite. Compare candidate versions on the same frozen plan, retain raw captures and version the schema, labels, normalization, evaluator and gates. Review errors by field, class and entity before release. The local fixture threshold is a teaching choice. Teams should set thresholds based on the harm and evidence required for each field. Human authorization remains separate from a passing evaluation.

## Knowledge Check

- A valid object omits the order key entirely. How does this differ from an object with a null order and an ambiguous reason?
- Which entries in a confusion matrix explain low replacement precision and low replacement recall?
- A scorecard shows 13/13 intent predictions correct, one critical wrong order and one unreviewed case. Which decision takes precedence, and what evidence belongs in the handoff?

## Knowledge Check Answers

- Omitting a required key is a schema failure. Explicit null with the right reason can pass schema and semantic checks if the reference supports ambiguity.
- Non-replacement rows in the replacement column contain false positives. The replacement row's non-replacement columns contain false negatives. Precision divides correct replacement predictions by all replacement predictions. Recall divides them by all actual replacement cases.
- BLOCK takes precedence for the confirmed critical failure. Keep the saved candidate, its source span, trusted target, denied route, and the unreviewed case as a separate evidence gap. A corrected candidate still needs completed evidence.

## Common Mistakes

- Counting the schema pass rate as field accuracy. Inspect entity, value and span errors separately.
- Treating empty values as successful extractions. Keep accuracy, extracted-value precision and recall, and review coverage distinct.
- Applying normalization to identifiers or currencies without authority. A format conversion needs a declared rule and evidence.
- Routing directly from candidate fields. Recheck the permitted operation, account, entity, value and escalation against independently trusted data.
