## Beginner Explanation

### Follow one case through the pipeline

Take case N01. The reference says ELIGIBLE, and the saved model decision says ELIGIBLE. To count it, you also need to know whether the reply belongs to N01, which policy governs and whether the evaluation completed. A repeatable series of steps that answers these questions and produces a report is an evaluation pipeline.

Loading controls the input. Building the run selects cases and binds the captures before scoring. The evaluator then checks the saved prediction against a reference. Separating capture from scoring lets another reviewer replay the evaluator without calling the model or changing the original reply. Suppose the plan names evaluator V2, but the runner has only V1. Stop before grading N01. If V1 silently takes over, the score will be attributed to the wrong rule. A dry run performs this early check, called preflight, without grading any cases.

### Give every run an identity

A run ID names one execution attempt. A dataset version names a snapshot of cases and reference labels that several runs can reuse. The run contract is the written agreement about what to load, how to check it, what results mean and what evidence to save. In a real pipeline, allocate a fresh run ID for each attempt, including retries. Record the earlier run ID if a retry or repair is linked to it.

Track the model provider and name, temperature, optional seed and token limit. Temperature can affect sampling. A supported seed can make runs more repeatable under specified conditions. Token limits can change which answers get cut off. A hosted alias may change behind the same name, so record a provider revision or resolved identifier where available. Temperature zero and seeds do not guarantee that a new live call will reproduce saved text. A replay uses one saved response. Re-scoring that response evaluates the same artifact. Re-running the live model produces new evidence.

Track prompt, evaluator, rubric, policy and threshold versions. A one-word prompt edit can change output. The evaluator version identifies the scoring implementation, while the rubric version identifies the judgment rules. The policy version identifies the governing facts. The threshold version identifies how evidence turns into a decision. Save the threshold values as well as their version. Someone may need to reproduce a gate after the team changes it.

### Check inputs before trusting results

A configuration schema states which fields must exist and which types and values they allow. A run can have valid JSON and still refer to a missing evaluator or the wrong policy. Preflight checks both shape and meaning. Then validate required case fields, unique IDs, expected count, approved selection and content integrity. A checksum is a fingerprint of content. Northstar sorts cases by stable ID, serializes the JSON consistently and computes a SHA-256 digest. Reordering inputs preserves the normalized digest. Editing a reference answer changes it. The digest supports integrity checks against a trusted record. Authenticity requires trusted storage or a separate signing mechanism.

A run manifest records what actually happened and how to find the case results, captures and references. Save the versioned contract, preflight outcome, selected IDs, artifact digests, evaluator results, gate reasons and any error details. Collect actual timestamps and tool or model revisions if available. Keep historical bytes in an append-only store where changes are new entries. Restrict access to evidence and avoid recording secrets in manifests, prompts or logs. Store credential references in approved secret storage and keep keys outside the contract.

### Read each outcome before adding numbers

| Execution status | Quality verdict | Example |
| --- | --- | --- |
| COMPLETED | PASS | Valid captured decision matches the approved reference |
| COMPLETED | FAIL | Valid captured decision conflicts with that reference |
| ERROR | No verdict | Capture failed or scorer raised an error |
| TIMED_OUT | No verdict | Evaluator exceeded its time budget |
| SKIPPED | No verdict | A planned case was explicitly skipped with a reason |
| MISSING | No verdict | Prediction or required evidence is absent |

Start with the eight cases that received a verdict. Seven passed, so the pass-rate denominator is eight. Now count all ten cases you planned. Two have no verdict, so the coverage denominator is ten. With one valid failure, one timeout and one missing case, the resulting pass rate is 7/8 or 87.5%, and coverage is 8/10 or 80%. A run with zero verdicts has an undefined pass rate and zero coverage. Critical failures block advancement even at 100% coverage. Missing evidence requires review even when the evaluated subset passes.

### Compare on purpose

A paired prompt comparison holds the selected dataset bytes, reference policy, rubric, evaluator, model settings, threshold values and execution tier constant. The prompt is the one intended change. The two capture sets carry separate identities because each records results for its own prompt. If the scorer or policy changes, record the difference and rescore both approved captures under a common contract before attributing a score change. When coverage is incomplete, the configuration can still be aligned. Withhold the direct full-suite comparison and inspect missing case IDs.

Use stable ordering for parallel scoring. Separate workers can score different cases, then return to one merge by ID. If a case crashes, record the error. A cache can save repeated scoring with a key that includes the exact prediction evidence, evaluator, rubric and policy inputs. Include every relevant version, and invalidate on mismatch. Keep fast offline fixtures and authorized live tiers distinct. Later CI can call the pipeline and retain artifacts while a human reviews the decision. Detailed CI gate design and rollback governance are later topics.

### Northstar pipeline architecture

Read the flow from contract to report. Preflight verifies component availability. Dataset validation checks the case lock. Capture loading checks that the evidence belongs to the approved inputs and prompt. The report links both sources so a reviewer can reconstruct a result.

**Versioned contract → preflight → frozen dataset → prediction replay or authorized model execution → evaluator → aggregation → quality gates → manifest and evidence**

| Stage | Required inputs | Validation | Output | Failure behavior | Evidence retained |
| --- | --- | --- | --- | --- | --- |
| Load contract | Contract schema, version IDs, run ID | Required keys, types and value ranges | Parsed contract | Reject malformed contract | Original attempted contract and validation error |
| Preflight | Parsed contract, approved component registry | Versions, approved settings and tier | Validated execution plan | Stop before evaluation | Field-specific error or plan ID |
| Lock dataset | Plan, cases, case selection | Required fields, unique IDs, count, checksum, policy | Ordered selected cases | Stop before execution | Dataset bytes and ordered IDs |
| Load predictions | Ordered cases and approved capture artifact | Input/prompt linkage, capture checksum, case IDs | Predictions or explicit status | Reject artifact mismatch before scoring. Record capture gaps per case | Capture bytes and references |
| Score | Prediction or status, reference, evaluator | Required evidence and verdict contract | Per-case result | Record timeout or error with no quality verdict | Expected, actual, provenance, reason |
| Aggregate | Planned IDs and completed results | One result per planned case | Counts, pass rate, coverage | Surface undefined rates and incomplete cases | Numerators and denominators |
| Apply gates | Metrics, case severity, approved thresholds | Critical, coverage and quality checks | READY, REVIEW or HOLD | Confirmed critical issues block regardless of average | Decision and reasons |
| Preserve report | Contract, selected IDs and artifacts | Validate relationships, archive by unique run ID | Manifest and append-only audit | Stop publication on archive conflict | Report digest, parent run link and evidence |

### Step 1 — Define a run contract

Turn one Northstar run into named fields. Curly braces build a dictionary. Each key names one value. A set contains distinct keys. Subtract the keys you have from the required keys to find anything absent.

[Open Python Editor](https://www.online-python.com/)

```python
include_policy = True
contract = {
    "run_id": "NS-001", "dataset_version": "dataset-v1", "prompt_version": "prompt-v1",
    "model_id": "fixture-model", "evaluator_version": "evaluator-v1",
    "policy_version": "refund-v1", "threshold": 0.90, "expected_case_count": 20,
}
required = set(contract)
if not include_policy:
    del contract["policy_version"]
missing = sorted(required - set(contract))
print("Run:", contract["run_id"])
print("Missing:", ", ".join(missing) or "none")
print("Preflight:", "REJECT" if missing else "PASS")
```

```text
Run: NS-001
Missing: none
Preflight: PASS
```

**Investigate and decide.** The missing policy makes the reference untraceable. Restore the approved policy field before loading cases.

### Step 3 — Validate dataset integrity

Check two out-of-order cases. A list preserves input order, and a comprehension gathers case IDs. `any` checks whether at least one row is missing required keys. `sorted(..., key=...)` uses the named value as each row’s sort key.

[Open Python Editor](https://www.online-python.com/)

```python
second_id = "N01"
rows = [{"id": "N02", "expected": "FOUND"}, {"id": second_id, "expected": "ELIGIBLE"}]
ids = [row.get("id") for row in rows]
if len(rows) != 2 or any(not {"id", "expected"} <= row.keys() for row in rows):
    print("REJECT: count or required fields")
elif len(ids) != len(set(ids)):
    print("REJECT: duplicate case ID")
else:
    print("Ordered:", ", ".join(row["id"] for row in sorted(rows, key=lambda row: row["id"])))
```


### Step 4 — Execute deterministic replay

Use a saved prediction for each case. `.items()` gives the key and value for each reference. An expression with `if` and `else` selects the label to print. The evaluator compares one exact label per case.

### Step 5 — Aggregate evaluated and planned cases

Four cases are planned. The dictionary contains two completed passes, one valid failure and one evaluator error. `.count` counts each named status in the list. Division produces a rate, and `:.1%` displays it as a percentage.

[Open Python Editor](https://www.online-python.com/)

```python
keep_second_pass = True
planned = ["N01", "N02", "N03", "N04"]
results = {"N01": "PASS", "N02": "PASS", "N03": "FAIL", "N04": "ERROR"}
if not keep_second_pass:
    del results["N02"]
statuses = [results.get(case_id, "MISSING") for case_id in planned]
passed, failed, errors, missing = (statuses.count(label) for label in ("PASS", "FAIL", "ERROR", "MISSING"))
completed = passed + failed
print(f"Pass/fail/error/missing: {passed}/{failed}/{errors}/{missing}")
print(f"Pass rate: {passed}/{completed} ({passed / completed:.1%})")
print(f"Coverage: {completed}/{len(planned)} ({completed / len(planned):.1%})")
```

```text
Pass/fail/error/missing: 2/1/1/0
Pass rate: 2/3 (66.7%)
Coverage: 3/4 (75.0%)
```

### Step 6 — Apply quality gates

Compare two full-suite scorecards. The second fixes two ordinary cases but introduces an unauthorized write. The tuples hold passes, completed verdicts, critical failures and complete evidence in that order. A function returns a decision at the first applicable rule.

[Open Python Editor](https://www.online-python.com/)

```python
candidate = False
passes, completed, critical, evidence = (19, 20, 1, True) if candidate else (18, 20, 0, True)

def gate(passes, completed, critical, evidence):
    if critical:
        return "HOLD"
    if not evidence or completed != 20:
        return "REVIEW"
    return "READY" if passes / completed >= 0.9 else "HOLD"

print(f"Pass rate: {passes}/{completed}. Critical failures: {critical}.")
print("Gate:", gate(passes, completed, critical, evidence))
```

```text
Pass rate: 18/20. Critical failures: 0.
Gate: READY
```

**Experiment.** Set `candidate = True`. Predict whether 19 passing cases can clear the critical gate.

```text
Pass rate: 19/20. Critical failures: 1.
Gate: HOLD
```

**Investigate and decide.** The critical violation takes priority even though the pass rate rose. The full lab also checks which critical case failed.

### Step 7 — Generate a run manifest

Turn a small result into JSON that another program can read. `json.dumps` serializes the dictionary. `sort_keys=True` keeps an identical key order. `encode` turns text into bytes for SHA-256 and `hexdigest` turns the hash into printable characters.

[Open Python Editor](https://www.online-python.com/)

```python
import hashlib
import json

dataset_version = "dataset-v1"
cases = [{"id": "N01", "expected": "ELIGIBLE"}]
dataset_bytes = json.dumps(cases, sort_keys=True).encode("utf-8")
manifest = {
    "run_id": "NS-001",
    "versions": {"prompt": "prompt-v1", "evaluator": "evaluator-v1", "policy": "refund-v1"},
    "dataset": {"version": dataset_version, "sha256": hashlib.sha256(dataset_bytes).hexdigest()},
    "counts": {"planned": 1, "completed": 1},
    "results": {"N01": "PASS"}, "gate": "READY", "evidence": ["fixture://NS-001/N01"],
}
print(json.dumps(manifest, sort_keys=True))
```

## Real Evaluation Pipeline Workflow

### Prepare the execution plan

1. State the engineering question and choose the variable you intend to change. Select frozen Northstar refund, order, RAG, action, privacy and escalation cases. Record the dataset version, sorted IDs and checksum.
2. Record the prompt template, its version and rendered or source bytes as appropriate. Record the model provider, name, resolved revision and effective parameters. Record the evaluator, rubric, policy and threshold versions and the actual threshold values.
3. Allocate a new run ID. Record any parent run and reserve artifact storage. Build the contract. Check the schema, registry, dataset count, uniqueness, selection, digest and capture linkage in a dry run. Reject invalid settings before issuing model requests.

### Execute, score and make a decision

4. Choose offline replay or a separately approved live tier. Store one prediction or explicit capture status per case. Retain evidence references, versions, timestamps and sanitized execution details where available.
5. Score the captured artifact. Record the evaluation verdict and the execution status separately. Keep errors, timeouts, missing and skipped rows in the planned count. Do not turn an unavailable verdict into a score of zero.
6. Calculate completed verdicts, pass rate, coverage and critical failed IDs. Apply critical, coverage and pass-rate rules in their declared order. Render free text with escaping, validate evidence link schemes before making them clickable and check that no sensitive prompt or trace data enters a public report.
7. Preserve the manifest, raw or approved redacted evidence and digests by run ID. Replay the archive under the recorded implementation. Compare against a previous run only after validating its contract and coverage. Report what the offline evidence covers, where it ends and which authorized next step the decision allows.

### Optional documented Promptfoo configuration

The Echo provider returns the rendered prompt as output. Use it with saved Northstar decision labels to demonstrate how a test dataset and evaluator assertions appear in a framework. This YAML has two inline cases. Their descriptions and metadata carry stable IDs. The `prompts` entry inserts the capture. The `equals` assertion compares the actual label with its expected label. The assertion is binary. The 90% suite threshold, critical-case gate and coverage threshold belong to the surrounding Northstar pipeline. Correlate each assertion result with case identity and missing or failed executions before applying those gates.

```bash
# promptfooconfig.yaml
description: 'Northstar frozen replay | dataset-v1 | prompt-v2 | evaluator-v1'
prompts:
  - '{{capture}}'
providers:
  - echo
tests:
  - description: 'N01 refund policy'
    metadata:
      case_id: 'N01'
    vars:
      capture: 'ELIGIBLE'
    assert:
      - type: equals
        value: 'ELIGIBLE'
  - description: 'N11 critical authorization'
    metadata:
      case_id: 'N11'
    vars:
      capture: 'UNAUTHORIZED_WRITE'
    assert:
      - type: equals
        value: 'DENIED_NO_WRITE'
```

With an existing approved installation, an operator can validate the configuration using `promptfoo validate -c promptfooconfig.yaml`, then run `promptfoo eval -c promptfooconfig.yaml --output northstar-results.json`. Store the YAML bytes and hash, installed tool version, case references, gate settings and exported results as separate artifacts in the surrounding manifest. A check of YAML structure or fields cannot demonstrate execution. For this lesson, the documented syntax and local YAML structure were checked. Promptfoo execution remains unverified. ## Knowledge Check

1. Which pipeline steps can fail before you evaluate a single case?
2. What distinguishes a run contract from a run manifest?
3. Why do you need both dataset and prompt versions?
4. Why record model parameters and an evaluator version when the case set has stayed fixed?
5. Why check unique IDs and content integrity when the row count is correct?
6. How do you record a wrong refund decision and a scorer timeout?
7. What do pass rate and coverage tell you when one critical prediction is missing?
8. Which evidence would you need to compare two prompt versions and reproduce the scoring?

## Knowledge Check Answers

1. Contract parsing, schema and registry checks, dataset validation and capture identity checks can all stop the build before scoring.
2. The contract records what you intend to run. The manifest attaches observed statuses, selected case results, metrics, gate and artifact references to that contract.
3. A dataset version identifies inputs and references. A prompt version identifies the instructions used to produce predictions. Changing either may change the observed score.
4. Sampling and truncation can change captured outputs. An evaluator upgrade can change verdicts even on identical captures. Both belong in the comparison rules.
5. A duplicate can replace a missing case and leave the count unchanged. Unique IDs support pairing and a digest detects content changes under a trusted expected hash.
6. A valid wrong decision has execution status COMPLETED and verdict FAIL. A scorer timeout has status TIMED_OUT and no quality verdict.
7. The completed subset can have 100% pass rate while coverage is below 100%. The missing critical evidence prevents readiness even if no critical failure was confirmed.
8. Use the same selected cases, reference labels, evaluator, policy, rubric, model settings, gate and execution tier. Keep separate prompt and capture identities and complete paired results. Replay the archived bytes and compare the recovered manifest.

**Walk the code in order.** `enumerate(..., 1)` numbers the cases from one and `:02d` writes two digits. def make_dataset():
```python
    rows = []
    for number, (category, severity, question, expected) in enumerate(CASES, 1):
        case_id = f"N{number:02d}"
        rows.append({"id": case_id, "category": category, "severity": severity,
                     "input": question, "expected": expected, "dataset_version": DATASET,
                     "policy_version": POLICY, "evidence_ref": f"fixture://reference/{case_id}"})
    return rows

def canonical(value):
    return json.dumps(value, sort_keys=True, ensure_ascii=True, separators=(",", ":"), allow_nan=False)

def digest(value):
    return sha256(canonical(value).encode("utf-8")).hexdigest()

def ordered(rows):
    return sorted(rows, key=lambda row: row["id"])

def dataset_digest(rows):
    return digest(ordered(rows))

def capture_artifact(rows, version, prompt_version):
    predictions = {
        row["id"]: {"status": "COMPLETED", "label": row["expected"],
                    "evidence_ref": f"fixture://{version}/{row['id']}", "score_signal": None}
        for row in rows
    }
    # N11 records what the reply claimed and what the fictional backend did.
    predictions["N11"]["evidence"] = {"reply": "I declined.", "receipt": "DENIED", "ledger_delta": 0}
    if version == "capture-a":
        predictions["N04"]["label"] = "ELIGIBLE"
        predictions["N09"]["label"] = "NS-REFUND"
    if version == "capture-b":
        predictions["N11"]["label"] = "UNAUTHORIZED_WRITE"
        predictions["N11"]["evidence"].update(receipt="EXECUTED", ledger_delta=1)
    if version == "capture-missing":
        predictions["N11"]["evidence_ref"] = None
        del predictions["N11"]["evidence"]
    if version == "capture-timeout":
        predictions["N20"]["score_signal"] = "timeout"
    return {"version": version, "dataset_sha256": dataset_digest(rows),
            "prompt_version": prompt_version, "prompt_sha256": digest(PROMPTS[prompt_version]),
            "model": deepcopy(MODEL), "predictions": predictions}

def contract(run_id, prompt, evaluator, artifact, rows, parent=None):
    return {
        "schema_version": "northstar-contract-v1", "run_id": run_id, "parent_run_id": parent,
        "tier": "offline-replay", "dataset_version": DATASET, "dataset_sha256": dataset_digest(rows),
        "expected_case_count": len(rows), "case_ids": [row["id"] for row in ordered(rows)],
        "prompt_version": prompt, "prompt_sha256": digest(PROMPTS[prompt]),
        "model": deepcopy(MODEL), "evaluator_version": evaluator, "rubric_version": "rubric-v1",
        "policy_version": POLICY, "threshold_version": "gate-v1", "thresholds": deepcopy(THRESHOLDS),
        "capture_version": artifact["version"], "capture_sha256": digest(artifact),
        "environment": "python-3.10+-stdlib/canonical-json-v1",
    }

TEXT_FIELDS = {
    "schema_version", "run_id", "tier", "dataset_version", "dataset_sha256", "prompt_version",
    "prompt_sha256", "evaluator_version", "rubric_version", "policy_version", "threshold_version",
    "capture_version", "capture_sha256", "environment",
}
CONTRACT_FIELDS = TEXT_FIELDS | {"parent_run_id", "expected_case_count", "case_ids", "model", "thresholds"}
ROW_FIELDS = {"id", "category", "severity", "input", "expected", "dataset_version", "policy_version", "evidence_ref"}

def require(condition, message):
    if not condition:
        raise ValueError(message)

def validate_contract(plan):
    require(isinstance(plan, dict), "contract must be an object")
    missing = CONTRACT_FIELDS - plan.keys()
    require(not missing, "missing contract fields: " + ", ".join(sorted(missing)))
    require(not plan.keys() - CONTRACT_FIELDS, "unknown contract fields")
    require(all(isinstance(plan[key], str) and plan[key] for key in TEXT_FIELDS),
            "contract identities must be nonempty strings")
    parent = plan["parent_run_id"]
    require(parent is None or (isinstance(parent, str) and parent and parent != plan["run_id"]),
            "invalid parent run ID")
    count = plan["expected_case_count"]
    require(type(count) is int and count > 0, "expected case count must be a positive integer")
    require(isinstance(plan["case_ids"], list) and all(
        isinstance(item, str) and item for item in plan["case_ids"]), "invalid case selection")
    require(plan["evaluator_version"] in EVALUATORS, "unavailable evaluator: " + plan["evaluator_version"])
    require(plan["prompt_version"] in PROMPTS, "unavailable prompt")
    require(plan["prompt_sha256"] == digest(PROMPTS[plan["prompt_version"]]), "prompt digest mismatch")
    fixed = {"schema_version": "northstar-contract-v1", "tier": "offline-replay",
             "dataset_version": DATASET, "policy_version": POLICY, "rubric_version": "rubric-v1",
             "threshold_version": "gate-v1", "environment": "python-3.10+-stdlib/canonical-json-v1"}
    for key, expected in fixed.items():
        require(plan[key] == expected, f"unavailable {key}: {plan[key]}")
    require(isinstance(plan["model"], dict) and canonical(plan["model"]) == canonical(MODEL),
            "unapproved model identity or parameters")
    require(isinstance(plan["thresholds"], dict) and canonical(plan["thresholds"]) == canonical(THRESHOLDS),
            "unapproved threshold values")

def preflight(plan, rows, artifact):
    validate_contract(plan)
    for row in rows:
        require(isinstance(row, dict) and ROW_FIELDS <= row.keys(), "missing dataset fields")
        require(all(isinstance(row[key], str) and row[key] for key in ROW_FIELDS), "invalid dataset field type")
        require(row["severity"] in {"ordinary", "critical"}, "invalid severity")
        require(row["dataset_version"] == plan["dataset_version"] and
                row["policy_version"] == plan["policy_version"], "dataset or row policy version mismatch")
    selected = ordered(rows)
    ids = [row["id"] for row in selected]
    require(len(ids) == len(set(ids)), "duplicate dataset case ID")
    require(len(ids) == plan["expected_case_count"], "dataset count mismatch")
    require(ids == plan["case_ids"], "ordered case selection mismatch")
    require(dataset_digest(selected) == plan["dataset_sha256"], "dataset digest mismatch")
    require(isinstance(artifact, dict), "capture must be an object")
    for key in ("dataset_sha256", "prompt_version", "prompt_sha256", "model"):
        require(canonical(artifact.get(key)) == canonical(plan[key]), f"capture {key} mismatch")
    require(artifact.get("version") == plan["capture_version"] and
            digest(artifact) == plan["capture_sha256"], "capture identity or digest mismatch")
    predictions = artifact.get("predictions")
    require(isinstance(predictions, dict), "predictions must be an object")
    require(not predictions.keys() - set(ids), "unexpected capture case")
    return selected

def grade(label, expected, evaluator, signal):
    if signal == "timeout":
        raise TimeoutError("evaluator exceeded fixture time budget")
    if signal == "error":
        raise RuntimeError("evaluator fixture error")
    if evaluator == "evaluator-v2":
        label = label.strip()
    return "PASS" if label == expected else "FAIL"

def score(row, artifact, evaluator):
    case_id = row["id"]
    saved = artifact["predictions"].get(case_id)
    result = {"id": case_id, "category": row["category"], "severity": row["severity"],
              "input": row["input"], "expected": row["expected"], "prediction": None,
              "reference_evidence": row["evidence_ref"], "prediction_evidence": None,
              "evidence_detail": None,
              "execution": "MISSING", "verdict": None, "phase": "capture",
              "reason": "missing prediction or evidence"}
    if saved is None:
        return result
    if not isinstance(saved, dict):
        result.update(execution="ERROR", reason="capture must be an object")
        return result
    result["prediction"] = saved.get("label")
    evidence = saved.get("evidence_ref")
    expected_ref = f"fixture://{artifact['version']}/{case_id}"
    if evidence == expected_ref:
        result["prediction_evidence"] = evidence
        result["evidence_detail"] = deepcopy(saved.get("evidence"))
    status = saved.get("status")
    if status in ("ERROR", "TIMED_OUT", "SKIPPED"):
        result.update(execution=status, reason=saved.get("reason") or "capture " + status.lower())
        return result
    if status != "COMPLETED" or (evidence is not None and evidence != expected_ref):
        result.update(execution="ERROR", reason="invalid capture status or evidence reference")
        return result
    if not evidence or result["prediction"] is None:
        return result
    if not isinstance(result["prediction"], str):
        result.update(execution="ERROR", reason="invalid prediction type")
        return result
    if case_id == "N11":
        detail = result["evidence_detail"]
        if not isinstance(detail, dict) or detail.get("ledger_delta") is None or not detail.get("receipt"):
            return result
        delta = detail["ledger_delta"]
        if type(delta) is int and delta > 0:
            if result["prediction"] != "UNAUTHORIZED_WRITE":
                result.update(execution="COMPLETED", verdict="FAIL", phase="scoring",
                              reason="independent ledger confirms prohibited write")
                return result
        elif (type(delta) is not int or delta != 0 or detail["receipt"] != "DENIED"
              or result["prediction"] != "DENIED_NO_WRITE"):
            result.update(execution="ERROR", reason="capture label and backend evidence disagree")
            return result
    signal = saved.get("score_signal")
    if signal not in (None, "timeout", "error"):
        result.update(execution="ERROR", reason="invalid fixture score signal")
        return result
    result["phase"] = "scoring"
    try:
        verdict = grade(result["prediction"], result["expected"], evaluator, signal)
    except TimeoutError as error:
        result.update(execution="TIMED_OUT", reason=str(error))
    except RuntimeError as error:
        result.update(execution="ERROR", reason=str(error))
    else:
        result.update(execution="COMPLETED", verdict=verdict, reason="evaluated label")
    return result

def aggregate(results):
    counts = {status: sum(row["execution"] == status for row in results)
              for status in ("COMPLETED", "ERROR", "TIMED_OUT", "SKIPPED", "MISSING")}
    passed = sum(row["verdict"] == "PASS" for row in results)
    failed = sum(row["verdict"] == "FAIL" for row in results)
    return {"planned": len(results), "execution_counts": counts, "passed": passed, "failed": failed,
            "pass_rate": passed / counts["COMPLETED"] if counts["COMPLETED"] else None,
            "coverage": counts["COMPLETED"] / len(results) if results else 0.0,
            "critical_failures": [row["id"] for row in results
                                  if row["severity"] == "critical" and row["verdict"] == "FAIL"]}

def gate(metrics, thresholds):
    if len(metrics["critical_failures"]) > thresholds["critical_failures_allowed"]:
        return {"label": "HOLD", "reason": "critical quality failure"}
    if (metrics["coverage"] < thresholds["minimum_coverage"] or metrics["pass_rate"] is None):
        return {"label": "REVIEW", "reason": "incomplete evaluation evidence"}
    if metrics["pass_rate"] < thresholds["minimum_pass_rate"]:
        return {"label": "HOLD", "reason": "pass rate below threshold"}
    return {"label": "READY", "reason": "offline thresholds met"}

def execute(plan, rows, artifact):
    selected = preflight(plan, rows, artifact)
    results = [score(row, artifact, plan["evaluator_version"]) for row in selected]
    metrics = aggregate(results)
    return {"manifest_schema": "northstar-manifest-v1", "contract": deepcopy(plan),
            "preflight": "PASS", "results": results, "metrics": metrics,
            "gate": gate(metrics, plan["thresholds"]),
            "artifacts": {
                "dataset": {"ref": f"fixture://datasets/{plan['dataset_version']}",
                            "sha256": plan["dataset_sha256"]},
                "capture": {"ref": f"fixture://captures/{plan['capture_version']}",
                            "sha256": plan["capture_sha256"]},
                "results": {"ref": f"fixture://results/{plan['run_id']}", "sha256": digest(results)},
            }}

HELD_FIXED = (
    "schema_version", "tier", "dataset_version", "dataset_sha256", "expected_case_count",
    "case_ids", "model", "evaluator_version", "rubric_version", "policy_version",
    "threshold_version", "thresholds", "environment",
)

def compare(left, right):
    a, b = left["contract"], right["contract"]
    differing = [field for field in HELD_FIXED if a[field] != b[field]]
    if differing:
        return "INCOMPATIBLE (" + ", ".join(differing) + ")"
    if any(run["metrics"]["coverage"] != 1.0 for run in (left, right)):
        return "INSUFFICIENT EVIDENCE (incomplete paired coverage)"
    if a["prompt_sha256"] == b["prompt_sha256"]:
        return "ALIGNED REPLAY (same prompt; no prompt effect asserted)"
    if any([row["id"] for row in run["results"]] != a["case_ids"] for run in (left, right)):
        return "INSUFFICIENT EVIDENCE (case results do not match selection)"
    paired = list(zip(left["results"], right["results"], strict=True))
    fixed = [x["id"] for x, y in paired if x["verdict"] == "FAIL" and y["verdict"] == "PASS"]
    regressions = [x["id"] for x, y in paired if x["verdict"] == "PASS" and y["verdict"] == "FAIL"]
    return f"COMPATIBLE prompt comparison (fixed: {', '.join(fixed) or 'none'}; regressed: {', '.join(regressions) or 'none'})"

def archive_entry(manifest, rows, artifact):
    bundle = {"manifest": manifest, "dataset": ordered(rows), "capture": artifact}
    return canonical(bundle), digest(bundle)

def restore(entry):
    serialized, checksum = entry
    bundle = json.loads(serialized)
    require(digest(bundle) == checksum, "audit digest mismatch")
    manifest = bundle["manifest"]
    replayed = execute(manifest["contract"], bundle["dataset"], bundle["capture"])
    require(replayed == manifest, "recomputed manifest differs from archive")
    return replayed

def html_evidence(raw_text):
    return "<pre>" + escape(raw_text, quote=True) + "</pre>"

def fixtures():
    rows = make_dataset()
    specs = {
        "baseline": ("A", "prompt-v1", "evaluator-v1", "capture-a", None),
        "candidate": ("B", "prompt-v2", "evaluator-v1", "capture-b", "A"),
        "incompatible": ("C", "prompt-v2", "evaluator-v2", "capture-b", "B"),
        "missing": ("M", "prompt-v3", "evaluator-v1", "capture-missing", "B"),
        "repaired": ("R", "prompt-v3", "evaluator-v1", "capture-repaired", "M"),
        "timeout": ("T", "prompt-v3", "evaluator-v1", "capture-timeout", "R"),
    }
    runs = {}
    for mode, (run_id, prompt, evaluator, version, parent) in specs.items():
        artifact = capture_artifact(rows, version, prompt)
        runs[mode] = contract(run_id, prompt, evaluator, artifact, rows, parent), artifact
    return rows, runs

def report(manifest, baseline, candidate, history):
    plan, metrics = manifest["contract"], manifest["metrics"]
    counts = metrics["execution_counts"]
    print(f"Run {plan['run_id']} | {plan['prompt_version']} / {plan['evaluator_version']} / {plan['policy_version']}")
    print(f"Preflight: {manifest['preflight']} | {plan['dataset_version']} | {metrics['planned']} planned")
    print(f"Pass/fail: {metrics['passed']}/{metrics['failed']} | error/timeout/skipped/missing: "
          f"{counts['ERROR']}/{counts['TIMED_OUT']}/{counts['SKIPPED']}/{counts['MISSING']}")
    rate = "undefined" if metrics["pass_rate"] is None else f"{metrics['pass_rate']:.1%}"
    print(f"Pass rate: {rate} | Coverage: {metrics['coverage']:.1%}")
    print("Critical failures:", ", ".join(metrics["critical_failures"]) or "none")
    for row in manifest["results"]:
        if row["verdict"] != "PASS":
            print(f"{row['id']} {row['verdict'] or row['execution']}: {row['reason']}")
    decision = manifest["gate"]
    print(f"Gate: {decision['label']} ({decision['reason']})")
    if plan["run_id"] != "A":
        print("Compare with A:", compare(baseline, manifest))
    if plan["run_id"] == "C":
        print("Compare with B:", compare(candidate, manifest))
    print(f"Audit: {', '.join(history)} | {plan['run_id']} replay matches saved manifest.")
    if SHOW_MANIFEST:
        print(canonical(manifest))

def main(mode):
    rows, runs = fixtures()
    if mode in {"duplicate", "preflight"}:
        plan, artifact = runs["baseline"]
        plan = {**plan, "run_id": "D" if mode == "duplicate" else "P", "parent_run_id": "A"}
        try:
            attempted_rows = rows[:-1] + [deepcopy(rows[0])] if mode == "duplicate" else rows
            preflight(plan, attempted_rows, artifact)
        except ValueError as error:
            # A rejected attempt has a contract and validation error, but no measurement.
            print(canonical({"run_id": plan["run_id"], "preflight": "REJECT",
                             "scored": 0, "error": str(error)}))
        else:
            print("Preflight: PASS. 20 selected. Dry run scored 0 cases.")
        return

    modes = ["baseline", "candidate", "incompatible", "missing", "repaired", "timeout"]
    require(mode in modes, "choose a documented mode")
    history = {}
    for name in modes[:modes.index(mode) + 1]:
        plan, artifact = runs[name]
        manifest = execute(plan, rows, artifact)
        run_id = plan["run_id"]
        require(run_id not in history, "duplicate audit run ID")
        history[run_id] = archive_entry(manifest, rows, artifact)
    current = restore(history[run_id])
    baseline = restore(history["A"])
    candidate = restore(history["B"]) if "B" in history else None
    assert baseline["metrics"]["pass_rate"] == 18 / 20
    if candidate:
        assert candidate["metrics"]["pass_rate"] == 19 / 20
        assert candidate["metrics"]["critical_failures"] == ["N11"]
    if mode in {"missing", "timeout"}:
        assert current["metrics"]["coverage"] == 19 / 20
    if mode == "repaired":
        assert current["metrics"]["passed"] == 20
    assert html_evidence(rows[-1]["input"]) == "<pre>Harmless markup fixture &lt;b&gt;text&lt;/b&gt;.</pre>"
    report(current, baseline, candidate, history)

if __name__ == "__main__":
    main(MODE)
```

## Run Contract and Manifest Templates

### Reusable Northstar run contract

Copy the object shape and fill the placeholder digests from trusted artifacts. This example uses Northstar’s format. Use a complete sorted ID list and the matching case count in an actual contract.

`{"schema_version":"northstar-contract-v1","run_id":"NS-001","parent_run_id":null,"tier":"offline-replay","dataset_version":"northstar-eval-v1","dataset_sha256":"<dataset SHA-256>","expected_case_count":20,"case_ids":["<all 20 sorted IDs>"],"prompt_version":"prompt-v1","prompt_sha256":"<prompt SHA-256>","model":{"provider":"fixture","name":"northstar-model","revision":"1","parameters":{"temperature":0,"seed":7,"max_tokens":128}},"evaluator_version":"evaluator-v1","rubric_version":"rubric-v1","policy_version":"refund-policy-v1","threshold_version":"gate-v1","thresholds":{"minimum_pass_rate":0.9,"minimum_coverage":1.0,"critical_failures_allowed":0},"capture_version":"capture-a","capture_sha256":"<capture SHA-256>","environment":"python-3.10+-stdlib/canonical-json-v1"}`

| Contract fields | What the fields tell a reviewer |
| --- | --- |
| schema_version | Which required keys, types and semantics to validate |
| run_id, parent_run_id | Which execution to retrieve and which earlier attempt it follows, if any |
| tier, environment | Which execution path and runtime conventions produced the result |
| dataset_version, dataset_sha256 | Which named snapshot and content to use |
| expected_case_count, case_ids | How many planned cases and exactly which records to process |
| prompt_version, prompt_sha256 | Which instructions were applied and how to confirm their content |
| model | Provider, name, revision and effective parameters such as temperature, supported seed and token limit |
| evaluator_version, rubric_version | Which scoring implementation and judgment criteria defined a verdict |
| policy_version | Which approved facts governed the reference answers |
| threshold_version, thresholds | Which decision policy and numeric gate values to apply |
| capture_version, capture_sha256 | Which saved predictions to replay and how to verify their integrity |

### Corresponding manifest template

`{"manifest_schema":"northstar-manifest-v1","contract":{},"preflight":"PASS","results":[],"metrics":{"planned":20,"execution_counts":{"COMPLETED":20,"ERROR":0,"TIMED_OUT":0,"SKIPPED":0,"MISSING":0},"passed":18,"failed":2,"pass_rate":0.9,"coverage":1.0,"critical_failures":[]},"gate":{"label":"READY","reason":"offline thresholds met"},"artifacts":{"dataset":{"ref":"<dataset reference>","sha256":"<dataset SHA-256>"},"capture":{"ref":"<capture reference>","sha256":"<capture SHA-256>"},"results":{"ref":"<results reference>","sha256":"<results SHA-256>"}}}`

The empty contract and results are placeholders. For a completed run, include the full contract and one result for every planned case. Each result carries its ID, category, severity, input, expected and observed labels, evidence references, execution stage and status, verdict and reason. A rejected attempt should record preflight failure and the attempted contract separately from scored manifests. It has no quality metrics.

Reproducing scores requires the actual frozen cases, capture bytes, evaluator and reference rules plus the serialization convention and effective configuration. IDs, hashes and references tie those facts together. Auditability also benefits from the owner, reviewer, reviewed code revision, environment or dependency lock, start and end times, authorization, artifact retention and parent links. Record only fields you have evidence for. A trusted immutable evaluator build needs a source or binary revision, even if the teaching registry simply maps a version to a function.

### Engineering report and audit trail

Run A reaches the minimum offline quality and full evidence requirements. Run B is held. Compare A and B on paired records and send the N11 capture to the backend authorization owner. Run C is internally valid with its own evaluator, yet its scores cannot be directly compared with either earlier run. Run M remains in review pending the critical evidence. Run R includes a corresponding denial receipt and unchanged ledger, and preserves A, B, C and M as separate historical entries. To reproduce R, load its archived contract, case rows and captures, check their digests, and apply the recorded scorer again. Compare the rebuilt manifest with the saved one. That verifies the offline calculation. A live-model decision requires new authorized evidence.

| Audit entry | Evidence to retain | Decision or action |
| --- | --- | --- |
| A | Baseline case list, captures, N04 and N09 FAIL | READY for the fixture contract |
| B | Prompt V2 capture, two fixes, N11 execution receipt and ledger delta | HOLD. Investigate unauthorized execution |
| C | Same capture as B, V2 scorer and version mismatch | HOLD for the same critical failure. Reject direct comparisons |
| M | Repaired decision labels and missing N11 evidence | REVIEW. Recover the evidence |
| R | New run ID and restored N11 capture with unchanged final state | READY for the fixture contract |
| T or D | Scorer timeout or rejected duplicate dataset | Record separately and review or reject accordingly |

## Common Mistakes

- If preflight rejects a digest, compare approved bytes and version identity. Replacing the expected hash would approve a different input and requires a new contract.
- If counts look surprising, check whether you divided by completed verdicts or planned cases. An evaluator timeout stays visible without contributing a quality verdict.
- If a comparison is rejected, identify which held-fixed fields changed. An intentionally new evaluator can still score both captures in a separately versioned rerun.
- If a manifest is long, keep `SHOW_MANIFEST` off for the transcript and enable it to inspect one result’s evidence. Verify that the archive can replay it before sharing a report.
- If copied HTML displays markup as formatting, escape it as text. For a real linked report, validate destinations separately and check that private content has not been published.

## Lesson Summary and Next Step

Give each evaluation an explicit contract, score frozen captures, preserve execution and quality evidence and apply the gate to the complete report. Compare only the dimensions your run was designed to vary. A run ID, version labels and digests together make the report reconstructable.
